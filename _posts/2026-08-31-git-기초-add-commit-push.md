Git을 처음 배우면서 가장 헷갈렸던 건 "왜 명령어를 세 번이나 쳐야 하나"였다.
파일을 고쳤으면 그냥 올라가면 되는 거 아닌가 싶었는데, 알고 보니 각 단계가 다른 일을 한다.

## 파일이 거쳐가는 4단계

| 단계 | 위치 | 넘어가는 명령어 |
|---|---|---|
| 작업 폴더 | 내 컴퓨터 | — |
| 스테이징 | 내 컴퓨터 | `git add` |
| 로컬 저장소 | 내 컴퓨터 | `git commit` |
| 원격 저장소 | GitHub | `git push` |

택배에 비유하면 이렇다.

- **작업 폴더** = 책상 위에 물건이 널려 있는 상태
- **스테이징** = 보낼 것만 골라 상자에 담기 (`git add`)
- **커밋** = 상자를 봉인하고 기록에 남기기 (`git commit`)
- **푸시** = GitHub으로 발송 (`git push`)

## 왜 상자가 따로 있나

처음엔 `add`가 불필요한 단계처럼 보였다. 그런데 이유가 있었다.

파일 10개를 고쳤어도 **관련 있는 3개만 골라서** 하나의 커밋으로 만들 수 있다.
저장소 안에는 올리면 안 되는 것도 있기 때문이다.

- `.env` 같은 비밀번호·API 키 파일
- 빌드 결과물, `node_modules` (수만 개 파일)
- 개인 메모, 테스트용 임시 파일

Git이 새 파일을 무조건 자동으로 담아버리면 이런 게 전부 공개된다.
그래서 Git은 "내가 봤는데, 담을지는 네가 정해"라는 태도를 취한다.

## git status 읽는 법

`git status -s`로 짧게 보면 맨 앞 두 글자가 각각 다른 뜻이다.

```
[1번칸][2번칸] 파일이름
```

- **1번 칸** = 상자 안 (스테이징됨)
- **2번 칸** = 책상 위 (아직 안 담김)

실제로 비교해보면 이렇다.

```
 M README.md    ← add 전: M이 2번 칸 (책상 위)
M  README.md    ← add 후: M이 1번 칸 (상자 안)
```

**M 하나가 한 칸 옮겨간 것**이 "담기 전 / 담은 후"의 차이다.
처음엔 `-s` 없이 그냥 `git status`를 쓰는 게 낫다.
`Changes to be committed`(상자 안)와 `Changes not staged for commit`(책상 위)으로 나눠서 친절하게 보여준다.

글자 뜻은 이렇다.

| 글자 | 의미 |
|---|---|
| `M` | Modified (수정됨) |
| `A` | Added (새로 추가됨) |
| `D` | Deleted (삭제됨) |
| `??` | 추적 안 되는 새 파일 |

## 오늘 실제로 겪은 실수

README에 이미지를 넣으려고 `figure/` 폴더를 만들고 사진을 넣었다.
README만 `add`하고 커밋했다면 **사진 파일은 GitHub에 안 올라가서 이미지가 깨졌을 것이다.**

`git status`를 쳐봤을 때 이렇게 나왔다.

```
 M README.md
?? figure/
```

`figure/`는 저장소 폴더 **안에** 있었는데도 `??`였다.
즉 저장소 안에 있다는 것만으로는 부족하고, `add`를 거쳐야 한다는 걸 여기서 확실히 알았다.

정리하면 이렇다.

| 상태 | GitHub에 올라가나 |
|---|---|
| 저장소 안에 있지만 add 안 함 (`??`) | ❌ |
| add만 하고 commit 안 함 | ❌ |
| commit했지만 push 안 함 | ❌ (내 컴퓨터에만) |
| commit + push 완료 | ✅ |

## 삭제도 push해야 반영된다

파일을 지운 것도 하나의 "변경사항"이라서 똑같이 `add` → `commit` → `push`를 거쳐야 한다.
Git 입장에서는 추가·수정·삭제가 모두 같은 급의 변경이다.

`git add`가 "추가한다"는 뜻이 아니라 **"이 변경사항을 다음 커밋에 포함시킨다"** 는 뜻이라
삭제에도 똑같이 쓴다는 걸 알고 나서 덜 헷갈렸다.

## push와 pull 방향

```
내 컴퓨터  ──push──▶  GitHub
내 컴퓨터  ◀──pull──  GitHub
```

밀어서 올리고(push), 당겨서 받는다(pull). 영어 단어 그대로였다.

## 아직 헷갈리는 것

파일을 지우고 같은 이름으로 새로 만들었는데, Git은 이걸 "새 파일"이 아니라 "수정"으로 기록했다.
Git이 파일을 **경로(이름)로 식별**하기 때문이라고 한다.
이름이 같으면 같은 파일로 본다는 뜻인데, 아직 완전히 익숙하진 않다.
