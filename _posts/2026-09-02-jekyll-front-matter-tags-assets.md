> 모두의연구소 AI 에이전트 과정 학습 기록입니다.
> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

블로그를 만들어 놓고 글을 쓰다 보니, **본문 말고 글에 붙는 정보들**을
따로 알아야 한다는 걸 알게 됐다. 태그, 안내 박스, 첨부파일 같은 것들이다.

## 태그는 본문에 쓰는 게 아니다

네이버 블로그나 인스타그램에 익숙하면 태그는 본문에 `#태그` 로 직접 치는 것이다.
Jekyll은 다르다.

```markdown
---
title: "글 제목"
tags: [git, github]      ← 여기가 front matter
---

본문은 여기부터              ← 화면에 보이는 내용
```

`---` 로 감싼 맨 위 구역을 **front matter** 라고 부른다.
글의 정보(제목, 날짜, 태그, 분류)를 적는 자리이고, 화면에 이대로 보이지 않는다.

| | 네이버·인스타 | Jekyll |
|---|---|---|
| 태그 위치 | 본문에 `#태그` 직접 입력 | front matter의 `tags:` |
| 본문에 보이나 | 글자로 그대로 보임 | 테마가 알아서 따로 표시 |

Jekyll은 이 정보를 읽어서 **태그 버튼, Tags 페이지, 태그별 글 모음을 자동으로 만든다.**
본문에 글자를 심는 게 아니라, 목록을 만드는 재료로 쓰는 것이다.

## 태그는 검색 노출 장치가 아니다

여기서 오해를 두 번 했다.

블로그 챌린지에 `모두의연구소` 라는 키워드 요건이 있어서
"키워드로 넣어달라"고 했더니 처음엔 태그에 들어갔다. 그런데 두 가지로 틀렸다.

**첫째, Jekyll의 `tags` 는 블로그 내부 분류용이다.**
검색엔진에 노출시키는 장치가 아니라, 내 블로그 안에서 글을 묶어주는 기능이다.

**둘째, 검색용 키워드를 넣는 자리라는 `<meta name="keywords">` 는 이미 죽은 기능이다.**
구글은 이 태그를 **2009년부터 무시한다.** 넣어도 검색에 아무 영향이 없다.

실제로 검색에 영향을 주는 건 이런 것들이다.

- 본문에 그 단어가 자연스럽게 등장하는지
- 제목
- meta description (검색 결과에 나오는 두어 줄 설명)
- 애초에 색인이 되는지 (`sitemap.xml`, `robots.txt`)

확인해보니 **이 블로그에는 `sitemap.xml`, `robots.txt`, meta description이 이미 다 있었다.**
Chirpy 테마가 기본으로 넣어주는 것들이라 따로 손댈 게 없었다.

**결론:** 태그는 "이 글이 무엇에 관한 글인가"를 나타내는 것이다.
`모두의연구소` 는 글의 주제가 아니라 이 기록이 나온 맥락이다.
그래서 **태그에서 빼고 본문에 명시**하는 쪽으로 바꿨다.

## 안내 박스 - Chirpy의 `prompt` 문법

모든 글 맨 앞에 넣기로 한 안내 박스가 이것이다.

```markdown
> 모두의연구소 AI 에이전트 과정 학습 기록입니다.
> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }
```

- **앞줄이 `>` 인용문이어야 작동한다.** 그냥 문단에 붙이면 아무 일도 안 일어난다
- `{: .prompt-info }` 는 바로 앞 인용문에 스타일을 입히라는 표시다
- 파란 정보 박스로 렌더링된다

넣기로 한 이유는 두 가지다.
챌린지의 키워드 요건을 본문에서 자연스럽게 채우면서,
동시에 **초안을 AI가 썼다는 사실을 밝히기 위해서**다.

## 첨부파일은 `assets/files/` 에

8/31 수업 퀘스트 대비로 만들었던 PPT를 블로그에 올렸다.

- 둘 곳: `assets/files/git-github-intro.pptx`
- 링크: `{{ site.baseurl }}/assets/files/git-github-intro.pptx`

두 가지를 배웠다.

**1. 원본 파일명이 한글이라 영문으로 바꿔서 복사했다.**
원본은 `Git_GitHub_입문.pptx` 였다. 파일명에 한글이 있으면 주소가 깨진다.

**2. 링크 앞에 `{{ site.baseurl }}` 을 붙여야 한다.**

GitHub Pages는 저장소 이름이 `사용자명.github.io` 일 때만 주소가 짧게 나온다.
내 저장소는 `blog_kate` 라서 주소가 이렇게 된다.

```
https://ctaleez51-art.github.io/blog_kate/
                                 ~~~~~~~~~ 이게 baseurl
```

그래서 `/assets/files/...` 라고만 쓰면 `/blog_kate` 가 빠진 주소를 가리켜 404가 난다.
`{{ site.baseurl }}` 은 `_config.yml` 에 적어둔 `/blog_kate` 로 바뀌어 들어간다.

## 정리

- front matter는 **글의 정보**를 적는 자리다. 본문과 분리돼 있다
- 태그는 **내 블로그 안에서 글을 묶는 기능**이지 검색용이 아니다
- `<meta name="keywords">` 는 구글이 2009년부터 무시한다
- Chirpy 안내 박스는 **앞줄이 `>` 인용문**이어야 작동한다
- 첨부파일은 `assets/files/` 에 두고, 링크 앞에 `{{ site.baseurl }}` 을 붙인다
