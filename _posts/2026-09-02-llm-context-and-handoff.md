> 모두의연구소 AI 에이전트 과정 학습 기록입니다.
> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

## 궁금했던 것

한 채팅창에서 대화를 계속 이어가다 문득 궁금해졌다.

**"이거 매번 처음부터 다 읽는 건가?"**

답은 **그렇다**였다. 그리고 이 사실 하나가 AI 에이전트를 어떻게 설계해야 하는지를
거의 다 결정한다는 걸 알게 됐다.

## LLM은 턴 사이에 기억이 없다

대화가 오갈 때 실제로 벌어지는 일은 이렇다.

- **매 턴마다 지금까지의 전체 대화가 입력으로 다시 들어간다**
- 턴과 턴 사이에 남아 있는 기억은 없다
- 사람은 이야기를 나눌수록 기억이 쌓이지만,
  LLM은 매번 **처음부터 기록을 다시 읽는** 방식으로 이어간다

"아까 말한 그거"가 통하는 이유는 기억해서가 아니라,
아까 한 말이 이번 입력에 통째로 다시 들어 있기 때문이다.

여기에 두 가지가 더 붙는다.

- **컨텍스트 윈도우에 한계가 있다.** 대화가 길어지면 앞부분이 요약·압축된다
- **새 창을 열면 완전한 백지다.** 어제 무슨 이야기를 했든 남아 있지 않다

## 에이전트 설계 제약으로 바꿔 적으면

| 성질 | 그래서 생기는 문제 |
|---|---|
| 컨텍스트가 유한하다 | 긴 작업은 중간 정보가 밀려난다 |
| 상태가 없다 | 외부에 남기지 않으면 이어지지 않는다 |
| 매번 전체를 다시 읽는다 | 길어질수록 비용과 시간이 늘어난다 |

결론은 하나로 모인다.
**실제 에이전트는 대화 기록에만 의존하지 않고, 작업 상태를 외부에 남기는 방식으로 설계한다.**

생각해보면 git 커밋도 성격이 같다.
머릿속에 "어디까지 했더라"를 담아두는 대신 저장소에 기록으로 남기는 것이다.

## 그래서 인수인계 파일을 만들었다

나는 수업 당일에 복습하지 않고 다음날 아침에 복습한다.
그래서 **매일 새 대화창**을 연다. 위에서 정리한 대로라면 새 창은 백지이므로,
어제까지의 맥락을 넘겨줄 방법이 필요했다.

담을 그릇은 두 가지가 있었다.

| 그릇 | 위치 | git에 올라가나 | 용도 |
|---|---|---|---|
| `CLAUDE.md` | 작업 폴더 안 | ⭕ (저장소라면) | 이 프로젝트에 대한 것 |
| 메모리 파일 | 설정 폴더 | ❌ | AI와 일하는 방식에 대한 것 |

결론은 **`CLAUDE.md` 한 파일에 폴더 구조 + 진행 상황 + 작업 규칙을 모두 담는 것**이었다.
새 창을 열면 이 파일이 자동으로 읽히므로, 사실상 유일한 인수인계 수단이 된다.

## 부작용도 하나 발견했다

인수인계 파일을 쓰다 보니 예상 못 한 문제가 나왔다.

8/31에 git 연습용 저장소를 만들면서 자기소개를 **가상으로 지어달라고** 한 적이 있다.
연습용이니 내용은 상관없었다. 그런데 그 지어낸 내용이
`CLAUDE.md`에도 **사실인 것처럼 적혀 있었다.**

- 지어낸 것: "비전공자, 관심 분야는 NLP"
- 실제: 세금 관련 콘텐츠를 만드는 1인 사업가

한 번 기록으로 남으면, 다음 세션은 그걸 **사실로 읽는다.**
매 턴 전체를 다시 읽는 구조라서, 잘못된 기록은 조용히 계속 재생산된다.

그래서 두 가지를 했다.

1. 블로그 About 페이지를 실제 정보로 전면 교체
2. `CLAUDE.md`에 **"여기 없는 것을 추측으로 채우지 말 것"** 이라는 경고를 명시

외부 기록이 상태를 대신한다는 건, **기록이 틀리면 상태도 틀린다**는 뜻이기도 하다.

## 정리

- LLM은 매 턴 전체 대화를 다시 읽는다. 기억이 아니라 재입력이다
- 컨텍스트는 유한하고, 상태는 없고, 길어질수록 비싸다
- 그래서 에이전트는 **작업 상태를 외부 파일에 남긴다**
- 다만 그 기록이 틀리면 틀린 채로 계속 이어진다.
  **무엇을 남기느냐만큼 그게 사실이냐가 중요하다**
