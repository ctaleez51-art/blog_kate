수업 퀘스트로 **짝이 원하는 게임을 만들어주는** 과제를 했다.

짝이 요청한 조건은 다섯 개였다.

- 오른쪽으로 가면서 장애물을 점프로 피하기
- 목숨 3개
- 목숨을 늘려주는 아이템
- 픽셀 그래픽
- **10분 안에 만들 수 있는 간단한 게임**

결과물은 이렇게 나왔다.

- 코드 <https://github.com/ctaleez51-art/pixel_runner>
- 플레이 <https://ctaleez51-art.github.io/pixel_runner/>

## 파일을 하나로 둔 이유

지난번에 만든 어휘 게임은 `index.html` / `styles.css` / `script.js` 세 개로 나눴다.
평가 기준이 셋을 나눠 언급했기 때문이다.

이번엔 **"10분 안에"** 라는 조건이 있었다.
받는 사람이 파일을 내려받아 더블클릭하면 바로 도는 편이 낫다고 봤다.

→ `index.html` **한 개.** 이미지 파일 없음, 외부 라이브러리 없음.

이 결정이 뒤의 선택들을 전부 결정했다. 그림도 소리도 파일을 못 쓴다는 뜻이기 때문이다.

## 1. 이미지 파일 없이 도트 그림 그리기

문자 배열을 색으로 바꿔서 1픽셀씩 찍는다. `.` 은 투명으로 처리한다.

```javascript
const HEART = [
  '.RR.RR.',
  'RRRRRRR',
  'RRRRRRR',
  '.RRRRR.',
  '..RRR..',
  '...R...'
];
```

글자가 그대로 그림이라서 눈으로 보면서 고칠 수 있다.
플레이어, 하트, 선인장을 전부 이 방식으로 만들었다.

캔버스는 480×240으로 작게 만들고 CSS로 2배 확대한다.
이때 **`image-rendering: pixelated` 를 빠뜨리면** 브라우저가 도트 사이를 부드럽게 섞어버려서
픽셀 느낌이 사라진다. 흐릿한 그림이 된다.

## 2. 음원 파일 없이 소리 내기

WebAudio로 파형을 코드에서 직접 만든다. 파일 하나로 끝내려면 이 방법뿐이다.

여기서 두 가지를 알게 됐다.

- 브라우저는 **사용자가 화면을 건드리기 전에는 소리를 막는다.**
  페이지가 열리자마자 소리를 내는 광고를 막으려는 장치다.
  그래서 첫 입력이 들어온 시점에 AudioContext를 만들어야 한다
- 부딪히는 "퍽" 소리는 **순수한 음만으로는 안 난다.**
  잡음(noise)을 섞어야 타격음처럼 들린다. 점프음은 순수한 음으로 되지만 충돌음은 아니다

## 3. 화면 주사율에 따라 게임 속도가 달라진다

`requestAnimationFrame` 은 "화면이 갱신될 때마다 불러줘"라는 뜻이다.
그래서 60Hz 화면과 144Hz 화면에서 **호출 횟수가 다르다.**
그대로 쓰면 주사율 높은 화면에서 게임이 두 배 빨라진다.

계산은 1/60초 고정 단위로 하고, 화면 갱신과 분리한다.

```javascript
acc += Math.min(now - last, 200);   // 탭 전환 후 한꺼번에 몰아치는 것 방지
while (acc >= STEP) { step(); acc -= STEP; }
draw();
```

`Math.min(..., 200)` 이 있는 이유는, 다른 탭에 갔다 오면 그동안 밀린 시간이
한꺼번에 들어와서 게임이 순간이동하기 때문이다.

## 4. 간격을 거리로 잴 것인가, 시간으로 잴 것인가

이 글에서 제일 남은 것이다. "하트가 너무 자주 나온다"는 지적을 받고 알게 됐다.

처음엔 하트 간격을 **거리(900~1600px)** 로 잡았다. 장애물과 같은 방식이었다.
그런데 이 게임은 진행할수록 속도가 빨라진다.

거리로 잡으면 **속도가 오를수록 같은 거리를 짧은 시간에 지나간다.**
즉 시간 기준으로는 점점 잦아진다.

| | 기준 | 이유 |
|---|---|---|
| 장애물 간격 | **거리(px)** | 속도가 올라도 넘을 거리가 확보돼야 한다 |
| 하트 간격 | **시간** | 등장 빈도가 체감 기준이다 |

실제 숫자로도 확인됐다.

| | 거리 기준일 때 | 시간 기준으로 바꾼 뒤 |
|---|---|---|
| 실제 간격 | 6.3~10.9초 | 15.6~24.6초 |
| 속도 3.2→7로 오르면 | 점점 짧아짐 | **그대로** |

같은 "간격"이라는 말을 쓰지만, 무엇을 위한 간격인지에 따라 **재는 단위가 달라진다.**

## 5. 클리어 가능한 게임인지 숫자로 확인하기

"내가 해보니 되더라"로는 확인이 안 된다. 최고 속도 구간까지 가보지도 못하기 때문이다.

그래서 **자동으로 점프하는 코드**를 붙여서 20,000프레임(약 333초) 돌렸다.

- 부딪힘 **0회**
- 점프 타이밍을 8~18프레임으로 바꿔가며 돌려도 전부 통과

이걸로 두 가지를 알 수 있다.
**최고 속도에서도 못 넘는 장애물이 없다는 것**, 그리고 **타이밍 허용 범위가 넓다는 것**이다.

"잘 되는 것 같다"가 아니라 숫자로 확인하는 방법이 있다는 게 이번 수확이다.

## 정리

- 파일 하나로 끝내기로 하면 그림도 소리도 코드로 만들어야 한다. 방법은 있다
- 확대한 픽셀 그림은 `image-rendering: pixelated` 가 없으면 흐려진다
- 브라우저는 사용자 입력 전에 소리를 막는다
- `requestAnimationFrame` 을 그대로 쓰면 화면 주사율이 게임 속도가 된다
- **장애물 간격은 거리, 아이템 간격은 시간.** 무엇을 위한 간격인지가 단위를 정한다
