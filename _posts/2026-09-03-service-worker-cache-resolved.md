블로그 글을 고쳐서 올렸는데 주소로 다시 들어가면 **옛 내용이 그대로** 보이는 문제가 있었다.
며칠을 끌었고, 결국 원인이 되는 기능을 **꺼버렸다가 다시 켰다.**

기술이 어려워서 며칠이 걸린 게 아니었다.
**확인하지 않은 설명을 사실처럼 듣고 있었기 때문**이었다.

## 내가 계속 물었던 것

> "어떻게 업데이트 안 된 내용을 계속 보여주냐. 그게 말이 되냐."

이 질문에 대한 답이 없는 채로 "끌까요, 되돌릴까요"만 반복됐다.
**판단할 근거가 없으니 결정을 할 수가 없었다.**

결국 관련 파일을 직접 열어봤고, 5분 만에 끝났다.

## 서비스 워커가 뭔가

먼저 이것부터 정리해야 했다.

**웹사이트가 방문자 브라우저 안에 설치해두는 작은 프로그램**이다.

- 페이지와 인터넷 사이에 끼어 있다
- 페이지가 서버에 뭘 요청하면 **서버보다 먼저** 이 프로그램이 받는다
- 서버에 넘길지, 갖고 있던 걸 대신 줄지를 **이 프로그램이 정한다**
- 페이지를 닫아도 브라우저에 남아 있다

Chirpy 테마에는 이게 기본으로 들어 있다. 오프라인에서도 열리게 하려는 기능이다.

**언제 바뀌나** — 그 프로그램 파일이 서버에서 바뀌었을 때.
설치돼도 바로 교체되지 않고 **대기** 상태로 있다가,
그 사이트 탭이 전부 닫히거나 사용자가 `Update` 를 누르면 교체된다.

## 코드를 열어보니

`sw.min.js` 의 핵심은 이 한 줄이었다.

```javascript
caches.match(요청).then(캐시된것 => 캐시된것 || fetch(요청))
```

캐시에 있으면 **서버에 아예 안 묻는다.** 최신인지 확인조차 안 한다.
여기까지는 "옛 글이 계속 보인다"는 증상과 맞다.

그런데 설정 파일 `swconf.js` 를 보니 이렇게 되어 있었다.

```
cacheName: 'chirpy-{빌드시각}'
```

`빌드시각` 은 **배포할 때마다 바뀐다.**
캐시 이름이 바뀌면 서비스 워커가 바뀐 것으로 취급되고,
그러면 방문자에게 **`New content available` 알림과 `Update` 버튼**이 뜬다.

누르면 이렇게 된다.

1. 새 서비스 워커로 교체
2. **이름이 다른 옛 캐시를 전부 삭제**
3. 페이지 새로고침

즉 "고쳐도 영영 옛 글이 보인다"가 아니라 **"`Update` 를 누르기 전까지"** 였다.
그 버튼은 이미 여러 번 본 적 있는 것이었다.

**끌 이유가 아니었다.** 그래서 껐던 것을 되돌렸다.

## 되돌리기 - `git revert`

캐시를 껐던 커밋을 되돌릴 때 쓴 명령이다.

```bash
git revert --no-commit 75222dd
```

- 파일을 손으로 고치는 것과 결과는 같지만,
  **그 커밋이 바꾼 것만 정확히 거꾸로** 적용해준다. 빠뜨릴 일이 없다
- `--no-commit` 을 붙이면 파일만 되돌려놓고 커밋은 내가 직접 한다

`git reset` 과 헷갈렸는데 이렇게 다르다.

| | `reset` | `revert` |
|---|---|---|
| 하는 일 | 커밋을 **없앤다** | **되돌리는 커밋을 새로 쌓는다** |
| 기록 | 사라짐 | 남음 |
| 이미 push한 것 | 곤란해짐 | 이걸 쓴다 |

이미 올라간 커밋은 없앨 수 없다. 그래서 `revert` 를 쓴다.

## 곁가지 - 한글 윈도우에서 파이썬이 UTF-8 파일을 못 읽는다

같은 날 겪은 다른 문제다. 검사 스크립트를 돌렸더니 파일 20개에서 전부 이 오류가 났다.

```
'cp949' codec can't decode byte 0xe2 ... illegal multibyte sequence
```

파일이 깨진 게 아니라, **파이썬이 한글 윈도우의 기본 인코딩(cp949)으로 읽으려 해서** 난 오류다.
UTF-8로 저장된 파일을 cp949로 해석하니 실패한다.

```bash
PYTHONUTF8=1 python 스크립트.py
```

앞에 `PYTHONUTF8=1` 을 붙이니 바로 통과했다. **코드는 한 글자도 안 고쳤다.**

## 이 건에서 남은 것

며칠이 걸린 이유는 기술이 아니었다.

- 화면을 볼 수 없는 상태에서 **기억으로 답한 설명**이 섞여 있었다
- 그 설명이 틀렸으니 나는 계속 "그게 말이 되냐"고 되물을 수밖에 없었다
- 코드를 열어보니 5분이면 끝날 일이었다

**틀린 정보로는 판단을 할 수 없다.**
"그게 말이 되냐"는 의심이 아니라, 앞뒤가 안 맞는다는 정확한 지적이었다.
설명이 이상하면 그건 내가 못 알아들은 게 아닐 수도 있다.

## 정리

- 서비스 워커는 브라우저 안에 설치되는 프로그램이다. 서버보다 먼저 요청을 받는다
- Chirpy는 캐시 이름에 빌드 시각이 들어가서, 배포할 때마다 `Update` 버튼이 뜬다
- 옛 글이 보이는 건 그 버튼을 누르기 전까지다. 기능을 끌 문제가 아니었다
- 이미 push한 커밋을 되돌릴 땐 `git revert`. `reset` 이 아니다
- `PYTHONUTF8=1` 로 cp949 디코딩 오류를 코드 수정 없이 넘길 수 있다
