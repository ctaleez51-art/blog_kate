수업에서 "SQL", "관계형 데이터베이스", "Redis" 가 한 자리에 나왔다.
나란히 놓인 말처럼 보였는데 아니었다. 하나씩 물어봤다.

## SQL - 데이터를 다루기 위한 언어

**Structured Query Language.**

데이터베이스에 저장된 데이터를 다루기 위한 언어다.
하는 일은 결국 넷이다.

- 넣고
- 찾고
- 고치고
- 지우고

이걸 **문장으로 요청한다.** 그래서 이름에 `Query`(질의)가 들어간다.

## 데이터베이스와 관계형 데이터베이스

여기서 오해하고 있었다.
두 말이 **나란히 놓인 두 종류**인 줄 알았는데, 그게 아니었다.

> **포함 관계다.**
> 데이터베이스가 큰 범주이고, 관계형은 **그 안의 한 갈래**다.
{: .prompt-info }

관계형 데이터베이스가 무엇이냐면 - 데이터를 담는 **방식**의 이름이다.

- 데이터를 **표**(행과 열)에 담는다
- 표와 표를 **공통된 값**으로 연결한다

이 연결이 **관계(relation)** 다. 이름이 여기서 나왔다.

예를 들어 회원 표와 주문 표가 따로 있고, 둘 다 회원 번호를 가지고 있으면
그 번호로 "이 주문은 누가 했나" 를 이어붙일 수 있다.

## "SQL은 관계형에만 쓰인다"는 틀리다

이렇게 알고 있었는데, 엄밀히는 틀린 말이었다.

맞는 부분은 있다. **SQL이 나온 배경도, 주된 무대도 관계형이 맞다.**
표를 다루기 위해 만들어진 언어다.

하지만 관계형이 아닌 데이터베이스나 다른 데이터 도구들도
**SQL 또는 그와 비슷한 문법을 조회 수단으로 제공한다.**

이유가 재미있다.
더 좋은 문법이 없어서가 아니라, **이미 많은 사람이 아는 언어라서**다.
새 문법을 만들면 아무도 못 쓴다.

## Redis - 표가 아닌 저장소

관계형이 아닌 저장소의 예로 나온 것이다.

가장 큰 차이는 **데이터를 어디에 두느냐**다.

| | 보통의 데이터베이스 | Redis |
|---|---|---|
| 저장 위치 | **디스크** | **메모리** |
| 속도 | 느리다 | **빠르다** |
| 전원이 꺼지면 | 남아 있다 | **사라진다** |
| 용량 | 크게 쓸 수 있다 | **작고 비싸다** |

저장하는 **형태**도 다르다. 표가 아니라 **이름과 값의 짝**이다.
이름을 대면 값을 꺼내주는 식이다.

## 이름에 뜻이 있었다

`Redis` 가 그냥 만든 이름인 줄 알았는데 줄임말이었다.

```
REmote DIctionary Server
```

- **Dictionary(사전)** - 이름을 대면 값을 꺼내주는 구조가 사전과 같다
- **Remote(원격)** - 그 사전을 내 컴퓨터가 아니라 **네트워크 너머에 두고** 쓴다
- **Server** - 그래서 서버다

구조를 그대로 이름으로 만든 것이다.

참고로 **회사 이름이 먼저가 아니다.** 오픈소스 이름이 먼저 있었고, 회사는 나중이다.

## 정리

- **SQL** 은 데이터를 넣고·찾고·고치고·지우기 위한 언어다
- 데이터베이스와 관계형 데이터베이스는 **포함 관계**다. 관계형은 한 갈래일 뿐이다
- 관계형은 데이터를 **표**에 담고, 표끼리 **공통된 값으로 연결**한다. 그 연결이 관계다
- "SQL은 관계형에만" 은 틀리다. 다른 곳에서도 쓴다. **이미 아는 사람이 많아서**다
- **Redis** 는 메모리에 두는 저장소다. 빠르지만 사라지고, 작고, 비싸다
- 이름은 **REmote DIctionary Server** - 구조가 그대로 이름이 됐다
