과제를 노션에 썼는데, 제출은 GitHub URL로 하라고 되어 있었다.
노션 페이지에는 GitHub 주소가 없다. 옮겨야 한다.

옮기는 과정에서 걸린 것들을 적어둔다.

## 저장소는 `Projects` 에서 만드는 게 아니다

내 GitHub 프로필에 들어가면 위쪽에 탭이 있다.

```
Overview  Repositories  Projects  Packages  Stars
```

`Projects` 라는 이름을 보고 여기서 새 프로젝트(저장소)를 만드는 줄 알았다. 아니었다.

`Projects` 는 **할 일을 카드로 늘어놓고 진행 상황을 관리하는 작업 관리 보드**다.
코드를 담는 곳이 아니라 "무엇을 언제까지 한다"를 정리하는 도구다.

저장소는 그 옆 `Repositories` 탭에서 만든다. 이름이 비슷해서 헷갈렸다.

## 다운받은 파일은 아직 GitHub와 아무 관계가 없다

노션 페이지 오른쪽 위 `···` 를 눌러 내보내기를 찾는데 메뉴에 안 보였다.
메뉴 맨 위에 `작업 검색...` 이라는 칸이 있어서, 거기에 이름을 치면 걸러진다.

형식은 `Markdown & CSV` 를 고르면 `.zip` 으로 받아진다. 풀면 `.md` 파일이 나온다.

여기서 한 번 막혔다. 파일은 이미 내 PC에 있는데, 이걸 어떻게 GitHub에 올리나?

**다운받은 파일은 그냥 파일이다. GitHub와 아무 연결이 없다.**
올리려면 그 파일이 **GitHub와 연결된 폴더** 안에 있어야 한다.

그 폴더를 만드는 명령이 `git clone` 이다.

```bash
git clone git@github.com:사용자명/저장소명.git 만들_경로
```

방금 만든 빈 저장소를 내 PC로 가져오는 것이다.
아무것도 없는 저장소라 "빈 저장소를 클론한 것 같다"는 경고가 뜨는데 정상이다.
파일은 안 딸려와도, **원격 주소 연결까지 같이 끝난다.** 그게 목적이다.

그 다음에 다운로드 폴더의 `.md` 를 이 폴더로 옮긴다.

## 작업 폴더가 저장소인 것은 아니다

내 작업 폴더는 이렇게 생겼다.

```
claudecode\
├── blog_kate\
├── voca_game\
└── PROJECT\      ← 이번에 clone으로 생긴 폴더
```

`claudecode` 폴더 자체는 git 저장소가 아니다.
그 안의 **하위 폴더 각각**이 저장소다.

그래서 `claudecode` 바로 아래에 파일을 넣으면 어느 저장소에도 속하지 않는다.
파일은 `PROJECT` 폴더 **안에** 들어가야 한다.

## 파일명이 그대로 주소가 된다

노션에서 내보낸 파일 이름은 이랬다.

```
[프로젝트] 자기 도메인 전달 형식 채우기.md
```

이대로 올리면 제출할 주소가 이렇게 된다.

```
.../blob/main/%5B%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8%5D%20%EC%9E%90...
```

주소에 못 쓰는 글자는 `%` 로 시작하는 코드로 바뀐다.

- 한글 → `%EA...` 같은 긴 코드
- `[` → `%5B`
- 공백 → `%20`

접속은 된다. 하지만 제출용으로 내밀 주소로는 읽을 수가 없다.

한글만 빼는 걸로는 부족했다. `[project] domain-format.md` 로 바꿔도
대괄호와 공백이 남아서 `%5Bproject%5D%20domain-format.md` 가 된다.

결국 `project_domain-format.md` 로 정리했다. 이러면 주소에 그대로 나온다.

## `LF will be replaced by CRLF` — 오류가 아니다

`git add` 를 했더니 경고가 떴다.

```
warning: in the working copy of 'project_domain-format.md',
LF will be replaced by CRLF the next time Git touches it
```

빨간 글씨가 아니라 `warning` 이다. add는 정상적으로 됐다.

줄바꿈을 표시하는 문자가 운영체제마다 다르다.
윈도우는 `CRLF`, 맥·리눅스는 `LF` 를 쓴다.
노션에서 내보낸 파일은 `LF` 인데, git이 윈도우에서 다룰 때 `CRLF` 로 바꾸겠다고
미리 알려주는 것이다. 내용에는 영향이 없다.

## 첫 push에만 붙이는 `-u`

```bash
git push -u origin main
```

`-u` 는 **앞으로 이 브랜치는 `origin/main` 과 짝이라고 등록해두는 것**이다.
한 번 해두면 다음부터는 `git push` 만 쳐도 된다.

"첫 push"는 그 저장소 기준이다. 다른 저장소와는 상관없다.
GitHub 쪽 저장소가 완전히 비어 있어서 브랜치조차 없었고, 이 push로 `main` 이 처음 생겼다.

## `Deployments` 가 없는 저장소에서 주소 찾기

블로그 저장소에서는 오른쪽 사이드바의 `Deployments` 에 들어가서 주소를 봤었다.
그런데 이번 저장소에는 그 항목이 아예 없었다.

`Deployments` 는 **배포를 한 적이 있는 저장소에만** 생긴다.
블로그는 GitHub Actions가 Pages로 배포하고 있어서 그 기록이 쌓인 것이다.

이번 저장소는 마크다운 파일 하나를 올린 것뿐이고, Pages를 켜지도 Actions를 돌리지도 않았다.
배포 기록이 없으니 항목 자체가 나타나지 않는다.

그리고 거기 있던 주소는 **배포된 웹사이트 주소**였다.
이번에 제출할 것은 사이트가 아니라 **GitHub 페이지 자체의 주소**다.

보는 곳은 브라우저 주소창이다. 저장소에서 파일을 클릭해 열면,
그때 주소창에 있는 것이 제출할 주소다.

```
https://github.com/사용자명/저장소명/blob/main/파일명.md
```

## 정리

노션 → GitHub는 결국 세 단계였다.

1. 노션에서 마크다운으로 내보낸다
2. `git clone` 으로 만든 저장소 폴더에 파일을 넣고 add → commit → push
3. GitHub에서 그 파일을 열어 주소창의 주소를 제출한다

막힌 지점은 git 명령어가 아니라 **"파일이 어디에 있어야 하는가"** 였다.
내 PC에 파일이 있다는 것과 그 파일이 저장소 안에 있다는 것은 다른 이야기였다.
