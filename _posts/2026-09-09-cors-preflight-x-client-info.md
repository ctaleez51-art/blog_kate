Edge Function을 배포하고 카드를 뽑으니 이게 떴다.

```
Failed to send a request to the Edge Function
```

문구만 보면 함수가 잘못됐거나 주소가 틀린 것 같다.
그런데 원인은 함수 밖에 있었다. **함수에 도달조차 못 한 상태**였다.

## 브라우저가 먼저 물어본다

브라우저는 다른 주소로 요청을 보내기 전에 한 번 먼저 물어본다.
"이런 방식으로, 이런 헤더를 붙여서 보낼 건데 받아주냐"고.
이걸 **preflight**라고 한다.

받아준다는 답이 와야 본 요청을 보낸다.
안 된다고 하면 **브라우저가 본 요청 자체를 막는다.**

그래서 오류 문구가 "요청을 보내지 못했다"였다.
서버가 오류를 돌려준 게 아니라, 요청이 나가지도 못한 것이다.
서버 로그를 봐도 아무것도 안 남는 이유가 이것이다.

## 빠진 것은 헤더 이름 하나였다

함수가 허용한다고 답한 헤더 목록에 **`x-client-info`** 가 없었다.

Supabase JS 라이브러리는 요청에 이 헤더를 **자동으로** 붙인다.
내가 코드에 쓴 적이 없으니 목록에 넣을 생각도 못 했다.
브라우저는 목록에 없는 헤더가 붙어 있으니 막았다.

고친 값은 이렇다.

```
"authorization, x-client-info, apikey, content-type"
```

네 개 다 라이브러리가 알아서 붙이는 것들이다.

## 고쳤는데 그대로였다

여기서 한 번 더 걸렸다. 로컬 파일을 고쳤는데 증상이 같았다.

**Edge Function은 서버에서 돈다.** 내 컴퓨터의 파일을 고쳐도
서버에 올라가 있는 것은 옛 코드 그대로다.

```powershell
npx.cmd supabase functions deploy interpret
```

다시 배포해야 반영된다.

배포할 때 이런 경고가 뜨는데 무시해도 된다.

```
WARNING: Docker is not running
```

로컬에서 함수를 돌려보려면 Docker가 필요하지만,
배포는 API로 올라가는 것이라 Docker 없이도 된다.

## 정리하면

- 오류 문구가 "보내지 못했다"면 서버가 아니라 **브라우저를 의심한다**
- 내가 안 쓴 헤더도 라이브러리가 붙인다. 허용 목록은 라이브러리 기준으로 짠다
- 서버에서 도는 코드는 **고치는 것과 올리는 것이 별개다**
