Supabase는 기본으로 **`Confirm email`** 이 켜져 있다.
가입하면 확인 메일이 가고, 링크를 눌러야 로그인이 된다.

**시간이 지나서 되는 게 아니라 링크를 눌러야 풀린다.**
기다리면 되는 줄 알고 한참 기다린 게 처음 오해였다.

## 확인 링크를 눌렀는데 "사이트에 연결할 수 없음"

링크를 눌렀더니 오류 화면이 떴다. 확인이 실패한 줄 알았다.

확인 링크는 두 가지를 **순서대로** 한다.

1. 계정 확인 처리
2. 원래 사이트로 되돌려 보내기

되돌려 보낼 주소가 **Site URL** 값인데, 기본이 `http://localhost:3000` 이었다.
내 로컬 서버는 5500번이라 그 주소에는 아무것도 없었다.

**확인 처리는 됐고, 되돌아오는 데서만 실패한 것이다.**
그래서 오류 화면을 본 뒤에도 로그인이 됐다.

1번과 2번이 붙어 있어서 하나로 보이는데, 실패한 건 2번뿐이었다.

## Site URL과 Redirect URLs는 다르다

코드에서 돌아올 주소를 직접 지정할 수 있다.

```js
sb.auth.signUp({ email, password, options: { emailRedirectTo: "..." } })
```

단, Supabase는 아무 주소로나 돌려보내지 않는다.
**`Redirect URLs` 에 미리 등록된 주소만** 허용한다.
등록 안 된 주소를 넣으면 무시된다.

| | Site URL | Redirect URLs |
|---|---|---|
| 역할 | 지정 안 했을 때 쓰는 기본값 | 허용 목록 |
| 와일드카드 | 불가 | 가능 |
| 개수 | 하나 | 여러 개 |

`http://localhost:5500/**` 처럼 `**` 를 붙이면 그 아래 모든 경로가 덮인다.

## 안내 문구가 없으면 고장난 사이트로 보인다

처음에는 확인이 필요한 경우에만 문구가 나갔고,
로그인 실패 시에는 Supabase가 준 영어 원문이 그대로 나갔다.

```
Email not confirmed
```

처음 온 사람이 이걸 보고 "메일함을 뒤져서 링크를 눌러야 한다"고 알 수가 없다.
비밀번호를 잘못 쳤나 하고 다시 치게 된다.

그래서 상황별로 한국어 문구를 넣었다.

| 상황 | 화면 |
|---|---|
| 가입 직후 | "○○ 로 확인 메일을 보냈습니다" + 재전송 버튼 |
| 확인 전 로그인 | "아직 이메일 확인이 안 됐습니다" + 재전송 버튼 |
| 비밀번호 틀림 | "이메일 또는 비밀번호가 맞지 않습니다" |
| 링크 만료 등 | "확인 링크 오류: ○○" |

재전송은 이렇게 한다.

```js
sb.auth.resend({ type: "signup", email, options: { emailRedirectTo } })
```

메일이 안 왔을 때 할 수 있는 게 있어야 막히지 않는다.

## 확인 전용 페이지를 따로 만들었다

처음에는 확인 링크가 첫 화면(`index.html`)으로 돌아왔다.
그러면 **자동으로 로그인된 상태**가 된다.
Supabase가 주소 끝(`#`)에 토큰을 붙여 보내고, 라이브러리가 그걸 읽어 로그인 처리를 하기 때문이다.

작동은 했는데 어색했다.
안내 문구가 뽑기 버튼 아래, 다른 안내문과 같은 회색 작은 글씨로 나왔다.
확인 완료 소식인데 뽑기 폼에 딸린 설명처럼 보였다.
게다가 그 자리는 원래 "해석을 받아오는 중"이 뜨는 칸이라, 카드를 뽑으면 덮여버렸다.

보통 쓰는 방식은 둘이었다.

1. **확인 전용 페이지** → "인증이 완료되었습니다" + 「로그인하기」 버튼. 로그인은 사용자가 직접
2. 로그인된 상태로 들여보내되, 화면 맨 위 띠로 안내하고 몇 초 뒤 사라지게

1번으로 정했다. `confirm.html` 과 `confirm.js` 를 만들고 `emailRedirectTo` 를 그쪽으로 돌렸다.

그 페이지가 하는 일은 이렇다.

- 토큰으로 자동 로그인됨
- **바로 `signOut()`**
- 완료 문구와 「로그인하기」 버튼 표시
- 주소창에 남은 토큰을 `history.replaceState` 로 지움

로그인시켰다가 바로 로그아웃시키는 게 이상해 보이지만,
링크를 여는 것만으로 로그인이 되는 걸 막으려는 것이다.

`SUPABASE_URL` 과 anon key가 두 파일에 중복되지 않게 **`config.js`** 로 분리했다.
