> 모두의연구소 AI 에이전트 과정 학습 기록입니다.
> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

타로 앱에 백엔드를 붙이면서 키를 세 개 만졌다.
셋 다 "키"라고 부르는데 공개해도 되는 것과 안 되는 것이 갈렸다.

| 키 | 누구를 위한 것 | 공개 가능? |
|---|---|---|
| Supabase **anon public key** | 앱을 쓰는 방문자 (브라우저) | 된다 |
| Supabase **개인 액세스 토큰** (`sbp_`) | CLI가 프로젝트 설정을 바꿀 때 | 안 된다 |
| **Claude API 키** (`sk-ant-`) | Edge Function이 Claude를 부를 때 | 안 된다 |

## anon key는 왜 공개해도 되나

이 키는 "어느 프로젝트에 손님 자격으로 왔다"는 표시일 뿐이다.
키가 지정하는 역할이 `anon`, 로그인 안 한 손님이다.

이것만 들고 오면 `readings` 테이블에서 아무것도 못 본다.
정책이 `auth.uid() = user_id` 인데 로그인이 없으면 `auth.uid()` 가 `null` 이라
걸리는 줄이 하나도 없다.

**막는 것은 키가 아니라 RLS 정책이다.**

키를 숨겨서 지키는 게 아니라, 키를 들고 와도 정책이 걸러내는 구조다.
그래서 브라우저로 내려보내도 된다.

## 로그인하면 그 위에 신분이 얹힌다

로그인하면 Supabase가 그 사람 전용 토큰을 따로 내준다.
이후 요청부터는 anon key와 그 토큰이 **같이** 간다.
그때 `auth.uid()` 에 값이 들어가고, 자기 줄만 보인다.

anon key가 없어지는 게 아니라 신분이 하나 더 붙는 것이다.

## 받은 키가 맞는 것인지 확인하는 법

anon key는 JWT다. 가운데 부분을 디코딩하면 `role` 과 `ref` 가 들어 있다.

- `role: anon` 이면 맞게 복사한 것
- `role: service_role` 이면 **잘못 복사한 것**

겉모양이 비슷해서 눈으로는 구분이 안 된다. 디코딩해서 확인해야 한다.

## `sbp_` 는 반대다

개인 액세스 토큰은 함수 배포, 시크릿 읽고 쓰기, DB 접근, 설정 변경까지 다 된다.

**시크릿을 읽을 수 있다는 게 특히 문제다.** 이걸 가진 사람은 Claude 키도 꺼내 볼 수 있다.
키 하나가 다른 키를 다 여는 셈이다.

## Claude API 키는 어디에 둘 것인가

목표는 하나였다. **Claude API 키를 브라우저에 두지 않는 것.**

가장 간단한 방법은 `script.js` 에 적는 것인데, 그 파일은 방문자 브라우저로 그대로 내려간다.
페이지 소스만 열면 누구나 볼 수 있고, 그 키로 남이 Claude를 부르면 요금은 나한테 온다.

anon key처럼 "공개돼도 정책이 막아준다"가 성립하지 않는다.
Claude API 키에는 나를 대신해 막아줄 정책이 없다. 키를 가진 만큼 쓸 수 있다.

## 그래서 서버를 하나 세웠다

키를 브라우저가 못 보는 곳에 둔다. 그게 Edge Function이었다.

```
브라우저 → (카드 이름, 질문) → Edge Function → (키 붙여서) → Claude
```

브라우저는 카드 이름과 질문만 보낸다. 키는 Edge Function 환경변수에만 있고,
함수 안에서 `Deno.env.get()` 으로 꺼내 쓴다.

정리하면 키 세 개를 이렇게 나눈 것이다.

- **anon key** — 브라우저에 둔다. RLS가 막아주니까
- **Claude 키** — 서버에 둔다. 막아줄 게 없으니까
- **`sbp_`** — 내 컴퓨터에만. 배포할 때만 쓴다
