> 모두의연구소 AI 에이전트 과정 학습 기록입니다.
> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

같은 과정을 듣는 분의 프로젝트를 코드 리뷰했다. 리뷰를 파일로 써서
그분 저장소로 PR을 보내는 것까지가 과제였다.

## 전체 흐름

포크는 이미 떠 있는 상태에서 시작했다.

```
포크(GitHub에서) → 클론(내 컴퓨터로) → 리뷰 파일 작성 → 커밋 → 푸시(내 포크로) → PR(원본으로)
```

클론은 작업용 폴더 안에서 했다. `git clone <주소>` 를 치면 그 자리에
저장소 이름으로 폴더가 하나 생긴다.

## 갈림길 — 리뷰 파일을 어디에 두느냐

여기서 한 번 멈췄다. 리뷰 파일을 클론한 저장소 **바깥**에 두면 내 메모로 끝난다.
저장소 **안**에 두어야 커밋할 수 있고, 커밋해야 PR로 보낼 수 있다.

PR로 보낼 것이었으므로 저장소 안에 넣었다. 파일 하나(`review.md`)가 전부다.

## 브랜치는 포크의 main 그대로 썼다

포크에서 보내는 PR은 이런 형태가 된다.

```
내계정:main → 원본:main
```

## Compare & pull request 배너가 안 떴다

푸시하고 나면 노란 배너가 뜬다고 들었는데 안 떴다. **새 브랜치를 밀었을 때 뜨는 배너**여서,
`main` 에 바로 밀면 안 뜬다.

대신 저장소 파일 목록 위쪽의 `Contribute` 버튼 → `Open pull request` 로 들어갈 수 있었다.

## 쓴 명령어

```bash
git clone git@github.com:내계정/저장소이름.git   # 포크를 내 컴퓨터로
git status --short                              # ?? = 아직 추적 안 되는 새 파일
git add review.md
git commit -F - <<'EOF'                         # 여러 줄 메시지
제목 줄

본문
EOF
git log origin/main..HEAD --oneline             # 아직 안 올라간 커밋
git push
```

## 오늘 처음 쓴 명령어 — `git ls-remote origin`

"푸시가 진짜 된 건가?"를 확인할 때 GitHub 화면을 열지 않고
원격에 있는 커밋 해시를 바로 보여준다.

```bash
git ls-remote origin
```

화면을 열어서 눈으로 확인하는 것과, 원격에 실제로 뭐가 있는지 값으로 확인하는 것은 다르다.
