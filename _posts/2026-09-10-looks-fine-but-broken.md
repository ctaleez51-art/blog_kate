코드 리뷰를 하면서 세 가지를 찾았다. 셋 다 **화면으로는 아무 이상이 없다.**
눈에 보이는 버그가 아니라서, 설정값·참조·파일 존재 여부를 따로 확인해야 나오는 종류였다.

## 1. 사이트 주소가 예시 주소 그대로였다

설정 파일에 이렇게 들어 있었다.

```js
site: 'https://example.com',
```

레이아웃 파일이 이 값으로 canonical 주소를 만든다. canonical은 검색엔진에게
"이 페이지의 원본 주소는 여기다"라고 알려주는 표시다.

배포된 사이트에 직접 들어가서 확인해보니 실제로 이렇게 나왔다.

```
https://example.com/foley
```

**화면에는 아무 이상이 없다.** 검색엔진에게만 남의 주소를 원본이라고 알려주고 있는 상태다.

코드만 읽었으면 `example.com` 이 눈에 안 들어왔을 것 같다.
실제 사이트에서 값을 찍어봤기 때문에 확인할 수 있었다.

## 2. 아무도 안 쓰는 파일이 남아 있었다

데이터를 DB로 옮기기 전에 쓰던 목업 파일(`sfx.json`)이 그대로 있었다.
참조하는 곳이 있는지 찾아봤다.

```bash
grep -rn "sfx.json" src/ astro.config.mjs package.json
```

결과가 비어 있었다. 아무도 안 쓴다는 뜻이다.

같은 데이터가 DB 마이그레이션 파일에도 들어 있어서, 나중에 어느 쪽이 진짜인지
헷갈릴 수 있는 상태였다.

## 3. 보내는 곳은 있는데 도착지가 없었다

카테고리 페이지가 없는 카테고리로 들어오면 `/404` 로 보내게 되어 있었다.
그런데 페이지 폴더에는 그 `404` 페이지가 없었다.

보내는 코드는 있는데 받는 파일이 없다. 이것도 정상적인 경로로 들어가면 안 만나게 된다.

## 정리

세 가지의 공통점은 **눌러봐서는 안 나온다**는 것이다.

- 1번은 배포된 사이트에서 값을 직접 찍어봐야 나왔다
- 2번은 `grep` 으로 참조를 세어봐야 나왔다
- 3번은 파일 목록을 봐야 나왔다

화면이 멀쩡하다는 것은 "문제가 없다"가 아니라 "화면에 나타나는 문제가 없다"까지다.
