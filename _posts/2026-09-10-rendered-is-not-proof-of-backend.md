> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

리뷰하면서 가장 오래 붙잡은 질문이다. **"이 앱에 백엔드가 붙어 있는가"를 무엇으로 판단하는가.**

처음에 나는 "사이트에 데이터 카드가 뜬다"를 근거로 삼았다. 그런데 이건 근거가 안 된다.
하드코딩된 배열 하나로도, JSON 파일 하나로도 똑같은 화면이 나온다.
실제로 그 저장소에는 같은 데이터가 JSON 파일로도 남아 있었다.

그래서 밖에서 확인할 수 있는 것부터 해봤다.

## 응답 헤더로 확인한 것

같은 주소를 두 번 불러서 응답 헤더를 봤다.

```
X-Vercel-Cache: MISS   (두 번 다)
X-Vercel-Id: 매번 다른 값
```

미리 만들어둔 정적 파일을 그냥 내려주는 것이라면 `PRERENDER` 나 `HIT` 로 나온다.
두 번 다 `MISS` 였다. **접속할 때마다 서버가 그 자리에서 만들어 보낸다**는 뜻이다.

다만 여기까지가 한계다. 이건 "미리 구워둔 정적 파일이 아니다"까지만 말해준다.
그 서버가 **DB에 다녀왔는지는 헤더에 안 나온다.** 서버가 자기 안의 배열을 읽어서
만들어 보냈어도 헤더는 똑같이 나온다.

## 결국 근거는 코드였다

조회 부분에 이 줄이 있었다.

```js
if (error) throw error;
```

DB 조회가 실패하면 에러를 던져서 페이지가 아예 안 뜨게 되어 있다.
그러니까 **페이지가 정상으로 뜬다는 것 자체가 DB에서 값을 받아왔다는 뜻**이 된다.

화면이 근거가 된 게 아니라, 코드를 읽고 나서야 화면이 근거가 됐다.

## 밖에서 확실히 확인하려면

DB 값을 하나 고치고, **재배포 없이 새로고침만으로 화면이 바뀌는지** 보면 된다.
바뀌면 그때그때 DB를 읽는다는 뜻이다.

다만 이건 DB 권한이 있는 사람만 할 수 있다. 남의 프로젝트를 리뷰하는 입장에서는 못 한다.

## 정리

| 확인 방법 | 알 수 있는 것 |
|---|---|
| 화면에 데이터가 뜬다 | 아무것도 |
| 응답 헤더가 `MISS` | 정적 파일이 아니다 |
| 조회 실패 시 에러를 던지는 코드 | 페이지가 뜨면 DB를 다녀왔다 |
| DB 값 수정 후 새로고침 | 확실. 단 DB 권한 필요 |

"작동한다"고 말하려면 무엇을 봤길래 그렇게 말하는지가 같이 있어야 한다는 걸 배웠다.
