**기능 하나에 브랜치 하나.** 이렇게 하기로 하고 시작했다.
연습하려고 일부러 그렇게 한 것이다.

하루 만에 브랜치가 다섯 개가 됐고, 그 중 제대로 굴러간 건 절반쯤이다.

```
main
 ├─ login          로그인
 ├─ business       사업장 등록
 ├─ excel-mapping  엑셀 매핑
 ├─ upload         파일 업로드
 └─ card           카드 이용내역
```

## 1. 제일 큰 사고 — 공개 주소에 아무것도 없었다

이게 하루 중 제일 위험했던 것이다.

기능을 계속 만들고 있었다. 파일 업로드도 되고, 매핑도 되고, 연도 거르기도 됐다.
**전부 `upload` 브랜치에서 했다.**

그런데 GitHub Pages는 **`main` 브랜치를 보고 사이트를 만든다.**

`main`에는 로그인까지만 들어 있었다.
그래서 **공개 주소를 열면 로그인 화면만 나왔다.**
과제 제출용 주소인데, 채점자가 열면 아무것도 없는 상태였다.

내 컴퓨터에서는 다 되니까 됐다고 생각하고 있었다.

> **브랜치에서 만든 것은, 합치기 전까지 세상에 없는 것이다.**

합치는 것은 명령 하나다.

```bash
git checkout main; git merge upload
```

어려워서 안 한 게 아니라, **합쳐야 한다는 걸 생각 안 하고 있었다.**

## 2. 브랜치 하나에 기능 두 개가 들어갔다

`business` 브랜치는 사업장 등록을 만들려고 판 것이었다.

만들다 보니 개인정보 입력 화면도 같이 정해져서, 그냥 이어서 만들었다.
커밋도 하나로 묶였다.

결과적으로 **`business` 브랜치에는 사업장과 개인정보가 같이 들어 있다.**

지금은 문제가 없다. 둘 다 필요한 기능이고 어차피 합칠 거니까.
문제는 **되돌리고 싶을 때** 생긴다.
사업장 작업만 빼고 싶어도, 커밋이 하나라서 개인정보까지 같이 딸려온다.

브랜치를 나누는 이유가 이거였다는 걸 이때 알았다.
**따로 만들어야 따로 버릴 수 있다.**

## 3. 브랜치가 뒤처지면 옛날로 돌아간다

`excel-mapping` 브랜치를 만들어두고 다른 걸 먼저 했다.
그 사이 `main`에 로그인 기능이 들어갔다.

나중에 `excel-mapping`으로 돌아가 보니 **로그인이 없다.**
지운 게 아니라, 이 브랜치는 **로그인이 생기기 전에 갈라져 나온 것**이라 원래 없었다.

브랜치는 **갈라져 나온 시점에서 멈춰 있다.**
그 뒤에 `main`이 앞으로 나가도 따라오지 않는다.

여기서 다시 작업하려면 `main`을 먼저 가져와야 한다.

## 4. 브랜치마다 파일 구성이 다르다

시험용 서버를 띄우는 설정 파일(`.claude/launch.json`)을 만들어뒀는데,
**`main`에만 있다.** 다른 브랜치에는 없다.

그래서 서버를 켜둔 채 브랜치를 옮기면 이런 게 뜬다.

```
Deletion of directory '.claude' failed. Should I try again?
```

옮겨갈 브랜치에는 그 폴더가 없으니 지워야 하는데,
**서버가 그 폴더를 쓰고 있어서 못 지운다**는 뜻이다.

`n`을 치면 브랜치 이동 자체는 된다. 폴더만 남는다.
제대로 하려면 **브랜치를 옮기기 전에 서버를 끄는 것**이 맞다.

브랜치를 바꾸면 **작업 폴더 안의 파일이 실제로 바뀐다**는 걸 여기서 체감했다.
이름표만 바뀌는 게 아니었다.

## 5. 커밋을 되돌린 것

작업 중에 커밋을 두 번 잘못했다. 아직 정리가 안 끝났는데 커밋해버린 것이다.

아직 push 전이라 되돌릴 수 있었다.

```bash
git reset --soft HEAD~1
```

`--soft`는 **커밋만 취소하고 고친 내용은 그대로 둔다.**
파일은 손대지 않으니 작업이 날아가지 않는다.

이게 가능했던 건 **push를 안 했기 때문**이다.
올라간 다음에는 이렇게 조용히 못 없앤다.

## 배운 것

브랜치가 어렵다고 느낀 부분은 명령어가 아니었다.
`checkout`, `merge`는 몇 번 치면 손에 익는다.

어려운 건 **지금 내가 어느 브랜치에 있고, 그 브랜치에 뭐가 들어 있는지 계속 아는 것**이다.
그걸 놓치니까 다 만들어놓고 배포는 빈 화면이었다.

브랜치를 팔 때는 **왜 파는지, 무엇만 여기 넣을 건지, 언제 합칠 건지**를
같이 정해두는 게 맞겠다.
