종합소득세 신고서의 인적사항 칸을 앱에 옮겨 담으면서 정했다.
**여기 있는 정보는 다 필수다.** 하나라도 비면 신고서가 안 된다.

그래서 "필수로 만들어 달라"고 했더니, 막는 자리가 **두 군데**라는 걸 알게 됐다.

## 화면만 막으면 뚫린다

HTML에는 `required`라는 것이 있다. 칸에 이걸 붙이면 비워둔 채로 저장을 누를 수 없다.

```html
<input id="name" required>
```

여기까지만 하면 될 것 같은데, **이건 브라우저가 해주는 친절이지 잠금장치가 아니다.**
개발자도구를 열어서 `required` 글자를 지우면 그대로 넘어간다.
브라우저를 안 거치고 서버에 직접 보내는 방법도 있다.

그래서 **데이터베이스 쪽에도 같은 조건을 건다.**

```sql
alter table profiles alter column name set not null;
```

이러면 어떤 경로로 들어와도 이름 없는 줄은 저장되지 않는다.

| 어디에 거나 | 무엇을 하나 |
|---|---|
| 화면 (`required`) | 사용자에게 **바로 알려주는** 역할. 저장 누르기 전에 빨간 표시가 뜬다 |
| DB (`not null`) | 실제로 **막는** 역할. 뚫고 들어와도 거절한다 |

둘 중 하나만 하면 안 된다.
화면만 하면 뚫리고, DB만 하면 사용자는 왜 안 되는지 모른 채 영어 오류를 본다.

## "둘 중 하나"는 `required`로 쓸 수 없다

전화번호에서 막혔다. 일반전화와 휴대전화가 있는데, **둘 중 하나만 있으면 된다.**

`required`로는 이걸 표현할 수 없다. `required`는 **자기 칸 하나만** 본다.
옆 칸이 채워져 있는지 아닌지를 알지 못한다.

그래서 양쪽을 다르게 처리했다.

- **DB** — `check` 조건을 쓴다. 여러 칸을 같이 볼 수 있다
- **화면** — `required`를 떼고, 저장 버튼을 눌렀을 때 코드로 직접 검사한다

이때 화면에 뜨는 문구도 직접 정했다.

> 일반전화와 휴대전화 중 하나는 입력해야 합니다.

`not null`은 "이 칸이 비었다"까지만 말할 수 있다.
**"둘 중 하나"라는 말은 사람이 써줘야 한다.**

## 조건을 거는 순간 기존 줄이 걸린다

SQL을 실행했는데 오류가 났다. 이미 저장돼 있던 줄이 새 조건을 어기고 있었다.

시험 삼아 대충 채워 넣었던 개인정보 한 줄이었다. 빈 칸이 있었다.
**조건을 나중에 걸면, 이미 들어와 있는 줄이 먼저 걸린다.**

조건을 어기는 기존 줄을 먼저 지우고 나서 조건을 거는 순서로 SQL을 다시 짰다.
시험용 줄이라 지워도 괜찮았지만, 실제 서비스였다면 이건 큰일이다.
**필수 조건은 나중에 거는 것보다 처음에 거는 것이 싸다.**

그리고 Supabase SQL Editor에서 `delete`나 `alter table`이 들어 있으면
`Potential issue detected` 확인창이 뜬다.
**오류가 아니다.** 되돌릴 수 없는 명령이니 한 번 더 확인하는 것이고, `Run query`를 누르면 된다.

## DB만 조이고 화면을 안 올리면 영어가 샌다

이건 확인하다가 겪었다.

DB에 조건을 걸어두면, 조건을 어겼을 때 **Postgres가 영어로 된 오류**를 보낸다.
그 영어를 한글 문구로 바꿔주는 코드는 화면 쪽(`script.js`)에 있다.

그래서 **DB만 고치고 화면을 배포하지 않으면**, 사용자는 알아볼 수 없는 영어를 보게 된다.

> DB를 바꿨으면 화면도 같이 올려야 한다.

고친 곳이 두 군데니까 올리는 것도 두 군데다. 당연한 말인데 순서를 놓치기 쉬웠다.

## 필수를 잘못 걸면 못 들어오게 막는다

마지막으로, 필수를 거는 것이 늘 안전한 쪽인 것은 아니라는 걸 알았다.

사업장 등록 화면을 시험하다가 막혔다.
**공동사업자 칸에 뭐라도 써야 등록이 된다.** 혼자 하는 사업자는 적을 것이 없는데 막힌다.

원인은 화면 쪽에 붙은 `required` 하나였다.

```html
<input id="coOwners" required>
```

"다 필수"라는 말을 그대로 모든 칸에 옮긴 결과다.
**필수인지 아닌지는 칸마다 따져야 하는 것**이지, 한꺼번에 정할 수 있는 게 아니었다.

체크박스도 마찬가지다. 체크박스에 `required`를 걸면 "반드시 체크"가 되어버려서,
해당 없는 사람은 아예 등록을 못 한다.

막는 것도 설계다. 너무 안 막으면 쓰레기가 쌓이고, 너무 막으면 사람이 못 들어온다.
