수업에서 VS Code 한 화면에 노트와 Colab GPU 와 Claude 를 같이 놓고 쓰라고 했다.
그렇게 해두면 창을 오갈 일이 없어서 편하다.

그런데 참조 사진을 올리는 셀에서 막혔다.

```python
from google.colab import files
uploaded = files.upload()
```

이게 **VS Code 의 Colab 확장에서는 동작하지 않는다.**

## 왜 안 되나

브라우저에서 Colab 을 열면 파일 선택 창이 뜬다. 브라우저가 내 PC 파일을 읽어
구글 런타임으로 올려주기 때문이다.

VS Code 확장은 연결 구조가 다르다. 계산은 구글 쪽 런타임에서 돌고,
**그 런타임은 내 PC 파일 시스템을 못 본다.** 구글 저장소에 이슈로 올라와 있는
알려진 제약이다 (`colab-vscode` #250, #276).

내려받는 쪽(`files.download()`)도 같은 이유로 안 된다.
결과물은 왼쪽 Colab 파일 탐색기에서 직접 받거나 구글 드라이브를 거쳐야 한다.

## GitHub 에 먼저 올려두고 주소로 내려받게 했다

업로드를 포기하고, 참조 사진을 GitHub 저장소에 먼저 넣었다.
노트는 raw 주소로 그 사진을 내려받는다.

```python
저장소 = "https://raw.githubusercontent.com/<계정>/<저장소>/main/samples"
참조사진_URL = f"{저장소}/pose_{RUN_ID}.png"
```

## 우회했더니 설계가 나아졌다

이게 더 컸다. `files.upload()` 방식은 **실행하는 사람이 매번 사진을 고른다.**
채점자가 노트를 열어 돌리면 내 결과와 다른 그림이 나온다.
같은 코드인데 결과가 다르면 비교할 수가 없다.

주소로 내려받게 하면 **누가 언제 실행해도 같은 사진이 들어간다.**
과제 루브릭에 재현 항목이 있었는데, 제약을 피해가려던 게 그 항목을 그냥 만족시켰다.

## 남길 것

- 수업에서 알려준 구성이라도 **내 환경에서 되는지는 따로 확인**해야 한다. 창이 다르면 연결도 다르다
- 안 되는 걸 만나면 "무엇이 안 되나"보다 **"왜 안 되나"** 를 먼저 본다.
  런타임이 내 PC 를 못 본다는 걸 알면 우회로가 바로 보인다
- 입력을 고정된 주소로 바꾸는 건 우회가 아니라 그냥 더 나은 설계였다
