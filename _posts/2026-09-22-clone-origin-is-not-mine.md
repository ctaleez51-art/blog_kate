저장소 이름을 확인하다가 겸사겸사 앞단계 폴더의 remote 를 봤다.
이번 과제와 상관없이 본 것인데, 여기서 하나 걸렸다.

**[Git Bash에 칠 것]**

```bash
git remote -v
```

두 폴더 결과가 이랬다.

```
room-3d-demo  →  https://github.com/<수업 계정>/room-3d-demo.git   ← 수업 저장소
splat         →  https://github.com/ctaleez51-art/splat.git        ← 내 저장소
```

## 앞단계 폴더는 남의 저장소를 가리키고 있었다

앞단계는 수업에서 준 저장소를 clone 해서 쓴 것이다.
**clone 한 폴더의 `origin` 은 clone 해 온 곳**이다. 내 컴퓨터에 받아왔다고 내 것이 되지 않는다.

인수인계 문서에 "앞단계는 Pages 업로드가 아직 안 끝났다"고 적혀 있었다.
그래서 이어서 올리면 되는 줄 알았는데, **이 상태로는 push 할 곳이 없다.**
남의 저장소에 쓰기 권한이 없으니 거부된다.

clone 은 파일을 받아오면서 "어디서 받아왔는지"도 같이 적어둔다. 그게 `origin` 이다.
받아온 곳과 보낼 곳이 기본값으로 같게 설정되는 것뿐이다.

| | 받아오기 | 보내기 |
|---|---|---|
| clone 한 남의 저장소 | 된다 | 권한 없음 |
| 내가 만든 저장소 | 된다 | 된다 |

앞단계를 웹에 올리려면 내 계정에 저장소를 새로 만들고 `origin` 을 그쪽으로 바꿔야 한다.
(이번엔 제출물과 상관없어서 안 했다)

이번 과제 폴더는 저장소를 내가 만들어서 시작했기 때문에 처음부터 내 주소를 가리키고 있었다.
그래서 push 가 그냥 됐다. 같은 컴퓨터 안의 두 폴더인데 성질이 달랐던 것이다.

## 남길 것

**폴더가 내 컴퓨터에 있다는 것과, 그 폴더가 내 저장소를 가리킨다는 것은 별개다.**
받아온 폴더에 이어서 작업할 때는 `git remote -v` 를 먼저 본다.
push 할 때가 돼서 거부당하고 나서 알면, 그때는 커밋이 쌓여 있는 상태다.
