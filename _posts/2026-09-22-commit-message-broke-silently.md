여러 줄짜리 커밋 메시지를 넣었다. 커밋은 **성공했다.** 오류도 경고도 없었다.
그런데 `git log` 를 열어 보니 이렇게 들어가 있었다.

```
@
제목을 한옥 담장 모형으로, 폰 확인 결과 기재

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
@
```

첫 줄과 끝 줄에 `@` 가 하나씩 붙어 있다. 커밋 목록에서 제목 자리에 보이는 건 이제 `@` 한 글자다.

## 문법이 아니라 글자로 읽힌 것

PowerShell에서 여러 줄 문자열을 쓸 때는 here-string 을 쓴다.

```powershell
@'
여러 줄
문자열
'@
```

이걸 **Bash에 그대로 넣었다.** Bash에는 `@'` 라는 문법이 없다.
그러니 Bash는 그걸 문자열 시작 표시로 안 읽고 **그냥 `@` 라는 글자**로 읽는다.
그래서 메시지 첫 줄과 끝 줄에 `@` 가 남았다.

문법으로 읽혔으면 `@` 가 사라지고 안쪽만 남았을 것이다.
글자로 읽혔기 때문에 그대로 내용이 됐다. 그리고 내용이 됐으니 **오류가 날 이유가 없다.**

같은 원인으로 전에 한 번 `pathspec` 오류를 만난 적이 있다. 그때는 오류가 나서 바로 알았다.
이번엔 **같은 원인인데 증상이 달랐다.** 조용히 들어가 버렸다.

## 적어둔 것을 안 보고 또 밟았다

이건 아는 함정이었다. 내 블로그 작업 규칙 파일에
"PowerShell here-string 을 쓰면 메시지가 깨진다"가 적혀 있고, 바로 전날 글에도 같은 원인을 썼다.

**적어둔 것과 쓸 때 보는 것은 다르다.** 적어두는 것만으로는 안 밟히지 않는다.

## push 전이라 고칠 수 있었다

아직 push 전이었다. `--amend` 로 메시지만 다시 썼다. 이번엔 Bash 문법인 heredoc으로.

**[Git Bash에 칠 것]**

```bash
git commit --amend -F - <<'EOF'
제목을 한옥 담장 모형으로, 폰 확인 결과 기재

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
EOF
```

`<<'EOF'` 는 `EOF` 만 나올 때까지를 한 덩어리로 넘긴다.
`EOF` 를 따옴표로 감싸면 안쪽 내용을 셸이 건드리지 않는다.

## 남길 것

**셸이 둘이면 문법도 둘이다.** 지금 치고 있는 곳이 PowerShell인지 Bash인지 먼저 보고 쓴다.
여러 줄 문자열, 따옴표, 명령 이어붙이기가 전부 다르다.

| 하려는 것 | PowerShell | Bash |
|---|---|---|
| 여러 줄 문자열 | `@'` … `'@` | `<<'EOF'` … `EOF` |
| 명령 이어붙이기 | `;` | `&&` |
| curl | `curl.exe` | `curl` |

그리고 **push 전에 `git log -1` 을 연다.** 이 습관이 있으면 잡힌다.
push 하고 나면 메시지는 되돌리기 어렵다.
