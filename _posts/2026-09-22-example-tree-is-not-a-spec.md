고른 공간을 3D로 만들어 웹에 올리는 과제를 냈다. 주소까지 제출하고 나서
"저장소 이름 같은 걸 과제에서 정해줬던 것 같은데, 지금은 내가 맘대로 지은 이름이잖아"가 걸렸다.

## 원문이 내 컴퓨터에 없었다

먼저 작업폴더를 다 뒤졌다. 인수인계 문서, README, 스킬 파일, 앞단계 폴더, 그날 학습 기록까지
봤는데 **어디에도 저장소 이름 얘기가 없었다.** 앞단계 기록에는 이 과제 얘기 자체가 한 줄도 없었다.

여기서 "지정된 것 같다"를 추측으로 만들지 않았다. 없으면 없다고 하고 원문을 가져오는 게 맞다.
과제 원문을 붙여넣고 다시 봤다.

## 트리 그림만 보면 이름 지정처럼 보인다

```
my-open-space/
├── index.html
├── scene.sog
├── README.md
└── shots/
    └── viewer.png
```

`my-open-space/` 한 줄만 떼어 보면 저장소 이름을 정해준 것처럼 읽힌다.
그런데 트리 바로 윗 문장이 이것이었다.

> "저장소를 새로 하나 만들어도 되고, **이미 있는 저장소에 폴더를 하나 더 두어도 됩니다.**"

이름을 지정했다면 "폴더를 하나 더 두어도 된다"가 성립하지 않는다.
저장소를 새로 만들든 기존 저장소에 폴더를 두든 상관없다는 말이, 이름이 자유롭다는 말이다.

`my-open-space/` 는 **그 아래 파일 구성을 보여주려고 세운 예시 트리**였다.
지정된 것은 저장소 이름이 아니라 **파일 이름 네 개**였다.

| 항목 | 지정인가 |
|---|---|
| `my-open-space/` | ✕ 예시 |
| `index.html` | ○ |
| `scene.sog` | ○ |
| `README.md` | ○ |
| `shots/viewer.png` | ○ |

## 바꿨으면 제출한 주소가 죽는다

GitHub Pages 주소에는 저장소 이름이 그대로 들어간다.
`ctaleez51-art.github.io/splat/` 의 `splat` 이 저장소 이름이다.

지정으로 읽고 저장소 이름을 `my-open-space` 로 바꿨으면 **주소가 같이 바뀌어서
이미 제출한 주소가 404가 된다.** 제출은 이미 끝난 뒤였으니 그대로 죽는 것이다.

이름을 고치는 일은 파일 하나 고치는 것과 무게가 다르다.
확인이 끝나기 전에 손대지 않은 게 맞았다.

## 남길 것

**예시로 세운 이름과 지켜야 할 이름은 다르다.**
트리 그림은 구조를 보여주는 그림이지 이름표가 아니다.
그림만 떼어 보지 말고 **앞뒤 문장을 같이 읽는다.** 자유롭다는 말이 대개 그 근처에 있다.

그리고 원문이 손에 없으면 원문부터 구한다. 기억으로 짐작한 지정을 따르는 것이
지정을 안 지키는 것보다 나쁠 수 있다.
