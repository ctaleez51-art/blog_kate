제출한 과제를 항목별로 대조하다가 `git status` 에 이 줄이 떠 있는 걸 봤다.

```
M index.html
```

열어 보니 제목 두 줄이 지워진 상태였다.

```diff
-<title>내 방을 알갱이로</title>
-  <h1>내 방을 알갱이로</h1>
```

## 고쳤는데 아무 일도 안 일어난 상태

이번 과제는 방이 아니라 한옥 담장이다. 앞단계에서 만든 페이지를 가져다 쓰면서
제목만 옛것으로 남아 있었고, 그걸 지워놓은 채 멈춰 있었다.

**커밋도 push도 안 돼 있었다.** 그래서 사람들이 여는 주소에는
`내 방을 알갱이로` 라는 옛 제목이 그대로 떠 있었다.

전에 "고쳤다 ≠ 반영됐다"를 한 번 썼는데, 그때는 커밋과 push까지 끝내고
배포 단계에서 안 넘어간 경우였다. 이번엔 그보다 앞이다. **커밋조차 안 된 상태**였다.

| 단계 | 이번 상태 |
|---|---|
| 내 컴퓨터의 파일 | 고쳐짐 |
| 커밋 | ✕ |
| push | ✕ |
| 남이 여는 주소 | 옛것 |

내 편집기에서 보이는 것과 남이 여는 주소에 뜨는 것 사이에는 **커밋과 push 두 단계**가 있다.
둘 다 안 돼 있으면 아무 일도 일어나지 않는다.
그리고 **오류가 안 난다.** `git status` 를 안 열면 모른다.

## 지운 자리를 그냥 두지 않았다

제목을 지워놓고 새로 안 넣으면 페이지에 제목이 없는 채로 나간다. 두 군데를 채웠다.

- `index.html` 의 `<title>` 과 `<h1>` → **한옥 담장 모형**
  (`#hud h1` 스타일이 그대로라 화면 위 패널 제목도 같이 바뀐다)
- `README.md` 의 폰 항목 → 자리표시자 `내 폰 O초, 남의 폰 O초` 를
  **`휴대폰으로는 불러와지지 않아서 확인 못 함`** 으로

폰에서 3D가 안 그려지는 원인은 못 찾았다. 오류도 안 난다.
**못 한 것은 못 했다고 적었다.** 과제 원문도 이렇게 돼 있었다.

> "끝까지 못 가도 괜찮습니다. 어디서 왜 막혔는지를 설명할 수 있으면 그것으로 충분합니다."

빈칸이나 `O초` 로 두는 것보다 확인 못 했다고 적는 편이 사실에 맞다.
`O초` 를 그대로 두면 읽는 사람은 내가 빠뜨린 건지 못 한 건지 구분할 수 없다.

## 남길 것

**제출 전에 `git status` 를 연다.** 대조표에 체크가 다 차 있어도, 그 체크가
내 폴더 기준인지 올라간 것 기준인지는 별개다.
`M` 한 줄이 떠 있으면 아직 아무 데도 안 간 변경이 있다는 뜻이다.
