내 PoC 는 쓰기 전에 사람이 두 개를 켜둬야 한다. 받아적기 서버와 Ollama.
"🎤 를 누르면 알아서 켜지게 하면 되지 않나" 를 짚어봤다. **안 된다.**

## 왜 안 되나

웹페이지는 손님이다. **남의 컴퓨터에서 프로그램을 켤 권한이 없다.** 브라우저가 원천적으로 막는다.

버튼을 눌렀다고 권한이 생기는 것도 아니다.
버튼을 눌렀든 안 눌렀든 페이지가 하려는 일은 "이 컴퓨터에서 프로그램을 켜라" 이고, 그게 막히는 것이다.

웹페이지가 할 수 있는 건 **이미 켜져 있는** 서버에 말을 거는 것까지다.

이 선이 어디 있는지가 중요했다. 나중에 이걸 팔려면 브라우저 밖(실행파일)으로 나가야 한다는
결론이 여기서 나왔다. 웹 안에서 조금 더 다듬어서 해결될 문제가 아니었다.

## 그래서 사람이 켜야 하는데, 창이 두 개 뜬다

서버를 켜면 파워셸 창이 프롬프트를 안 돌려주고 멈춘 것처럼 보인다.
**멈춘 게 아니라 서버가 그 창에서 돌고 있는 것**이다.
문제는 쓸 때마다 검은 창 두 개를 띄워놓고 있어야 한다는 것이었다.

창 없이 돌리는 법을 찾았다.

**[파워셸에 칠 것]**

```powershell
Start-Process python -ArgumentList "받아적기.py" -WindowStyle Hidden -RedirectStandardOutput "받아적기-기록.txt" -RedirectStandardError "받아적기-오류.txt"
```

- `-WindowStyle Hidden` — 창이 안 뜬다
- `-RedirectStandardOutput` — 화면에 찍히던 것을 파일로 받는다.
  건별 소요 시간이 여기 쌓이니 나중에 검증할 때 그대로 재료가 된다
- `-RedirectStandardError` — 오류는 따로 받는다. 창이 없으면 오류도 안 보이므로 이게 있어야 한다

Ollama 는 `ollama serve` 대신 **시작 메뉴의 앱**으로 켜면 트레이에서 돌고 창이 없다.

## 남길 것

**"창이 떠 있어야 한다" 가 아니라 "서버가 돌고 있어야 한다" 였다.**
이 둘을 구분하니 창을 없앨 수 있었다. 창은 서버가 도는 방식 중 하나일 뿐이었다.

창을 숨길 때는 **화면에 찍히던 것을 어디로 보낼지 같이 정한다.**
안 정하면 잘 돌 때는 조용해서 좋고, 죽을 때도 조용해서 원인을 못 본다.
