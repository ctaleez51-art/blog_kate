PoC 를 제출하기 전에 문서를 처음부터 다시 읽었다. 네 가지를 걸러냈다.
코드보다 여기서 잡은 게 많았다.

## ① 확인되지 않은 기록이 들어가 있었다

`모델선정근거.md` 에 "프롬프트를 다듬은 기록" 이라는 표가 있었다.
그중 한 줄이 **"식사비를 식비로 분류했다 → 접대비 보기를 넣었다"** 였다.

읽다가 걸렸다. **지금 프롬프트에 접대비가 없다.**
계정과목은 애초에 모델에게 안 맡기기로 한 항목이다. 있었을 수 없는 일이었다.

실제로 있었던 일이 아니라 그럴듯하게 지어진 줄이었다.
나머지 줄도 실제 기록인지 확인할 방법이 없어서 **표를 통째로 뺐다.**

**확인 안 된 것을 제출 문서에 두는 것보다 없는 편이 낫다.**
근거 문서에 지어낸 근거가 한 줄 섞이면 나머지 줄도 같이 못 믿게 된다.

잡아낼 수 있었던 건 **내가 내린 결정을 알고 있었기 때문**이다.
계정과목을 안 맡기기로 한 게 내 결정이라, 그 표가 내 결정과 어긋나는 게 바로 보였다.

## ② 제출물이 아닌 작업 문서가 저장소에 올라가 있었다

`HANDOFF.md`, `체크리스트.md` 는 내부 인수인계용이다. 제출물은 다섯 가지뿐이다.
`colab.ipynb`, `검증돌리기.py`, `검증-원자료.json` 도 이번 검증에 안 쓴 것들이었다.

파일은 내 폴더에 남기고 저장소에서만 뺐다.

**[파워셸에 칠 것]**

```powershell
git rm --cached 체크리스트.md HANDOFF.md
```

`--cached` 가 핵심이다. **작업 폴더에서는 지우지 않고 추적만 끊는다.**
그냥 `git rm` 이면 파일까지 사라진다. 나는 계속 쓸 파일이라 남겨야 했다.

## ③ 성공 기준을 결과에 맞추자는 제안

성공 기준이 10건 중 10건인데 결과가 7건이라, 기준을 고칠지 묻는 제안이 나왔다.

**안 고쳤다.** 기준을 결과에 맞춰 내리면 검증이 아니라 조작이다.
기준 10건, 결과 7건, 못 미쳤다고 그대로 적었다.

기준은 **재기 전에** 정하는 것이고, 재고 나서 바꾸면 그 기준은 아무것도 판정하지 못한다.
못 미친 이유를 세 갈래로 갈라 적은 게 기준을 내리는 것보다 쓸모 있었다.

## ④ 과제 문서에 다른 이야기가 섞여 있었다

README 에 "남의 컴퓨터에서는 🎤 가 안 된다 / 이 구조는 파는 물건이 아니다" 가 들어가 있었다.

맞는 말이다. 하지만 **과제 제출 문서에 들어갈 내용이 아니다.**
과제 요건은 "다른 사람이 실행해도 같은 결과가 나오게, 실행 방법을 README 에 정리" 이고,
설치 방법이 적혀 있으면 충족된다. 이 절을 지웠다.

맞는 말인지와 여기 들어갈 말인지는 다른 질문이다. **문서마다 받는 사람이 다르다.**

## 남길 것

제출 직전 점검은 코드가 도는지가 아니라 **문서가 사실인지**를 본다.

- 문서에 적힌 일이 **실제로 있었던 일인지** 내가 대조한다
- 저장소에 든 것이 **제출물인지** 센다
- 기준은 결과를 보고 바꾸지 않는다
- 맞는 말이어도 **그 문서에 들어갈 말인지** 따로 본다
