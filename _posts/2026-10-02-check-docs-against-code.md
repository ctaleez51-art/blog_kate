> 모두의연구소 AI 에이전트 과정 학습 기록입니다.
> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

제출 문서의 테스트 표에는 "전부 일치", "통과" 같은 결과가 적혀 있었다. 문서 초안은 AI가 썼다. 그래서 **이 결과를 실제로 확인하고 쓴 건지** 물었고, 하나씩 다시 확인했다.

## 다시 돌려서 확인한 것

예시 CSV 4개(1,200행)를 지금 코드에 넣고 계산해서 정답표와 비교했다.

| 항목 | 결과 |
|---|---|
| 월별·채널별 지표 숫자 | 180개 모두 같음 |
| 전월 대비 증감률 | 8개 모두 같음 |
| 비교한 달 (이번 달·전 달) | 2개 같음 |
| 쿠팡 경쟁가 열세 제품 | 8개 목록 같음 |

문서의 "190/190"은 숫자 188개와 비교 달 2개를 합친 수였다. 잘못된 CSV 4종류(빈 파일, 필수 열 누락, 숫자 아닌 값, 날짜 형식 오류)를 넣으니 오류 안내가 문서대로 나왔다.

## 확인하지 못한 것

| 항목 | 이유 |
|---|---|
| DB 권한 시험 | Supabase DB에 직접 돌려야 하는 시험이라 로컬에서 확인 불가 |
| 로그인 | 배포 사이트에서 실제로 회원가입해야 함 |
| AI 응답 시간, 답변 속 숫자 | 실제 AI를 불러야 알 수 있음 |

확인 못 한 것은 "확인 못 함"으로 남긴다. 다른 사람이 해 봐야 하는 것은 누가 하면 되는지도 같이 적는다.

## 코드에 근거가 있는지 찾기

체크리스트 문장마다 코드에 그 동작이 있는지 찾아봤다.

- 결제 취소 안내 문구 → 결제 화면 코드에 그대로 있음
- 로그인 없이 부르면 401, 하루 한도를 넘으면 429 → AI 서버 코드에 있음
- 정답 시나리오 **문서** → 저장소에 파일이 없음. 요약만 다른 문서에 있었다

"있다"고 체크된 것이 실제로는 없는 경우가 있었다.

## 고쳤다고 했는데 안 바뀐 수정

문서를 고치는 중에, 수정 창에서 수락했는데 앱에는 거부로 기록되어 **파일이 그대로인** 일이 있었다. 화면에서 수락을 눌렀다는 것과 파일이 바뀌었다는 것은 별개다.

그 뒤로는 고칠 때마다 파일을 다시 열어서 그 줄이 실제로 바뀌었는지 확인했다.

## 남길 것

- 문서의 "통과"는 **누가, 언제, 무엇으로** 확인했는지 내가 물어본다
- 다시 돌릴 수 있는 건 다시 돌려 본다. 못 돌리는 건 못 돌렸다고 적는다
- 고친 뒤에는 파일을 열어 실제로 바뀐 것을 본다
