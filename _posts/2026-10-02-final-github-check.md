팀프로젝트 문서를 다 올린 뒤, 제출 전에 GitHub 저장소를 마지막으로 점검했다. 본 것은 네 가지다.

## 1. 비밀 키가 올라가 있지 않은가

```bash
git grep -nE "sk-[A-Za-z0-9]{10,}|test_sk_[A-Za-z0-9]|live_sk_|sb_secret_|eyJhbGciOi" -- . ':!*.md'
```

- `git grep`: git이 추적하는 파일 안에서만 찾는다. 올라간 것만 보면 되니까 이게 맞다
- 찾은 모양: OpenAI 키(`sk-`), 토스 시크릿 키(`test_sk_`, `live_sk_`), Supabase secret 키, JWT(`eyJ...`)
- `':!*.md'`: 문서 속 설명 글은 빼고 찾는다

나온 것은 "secret 키는 넣지 마세요" 같은 **주석뿐**이었다. 브라우저 설정 파일에는 공개해도 되는 키(Supabase publishable 키, 토스 클라이언트 키 `test_ck_`)만 있었다.

## 2. 시험 파일에 개인정보가 없는가

쿠팡·네이버 주문내역 원본 모양의 시험 CSV를 올려 두었다. 실제 원본에는 구매자 이름, 전화번호, 주소 칸이 있다. 제목 줄을 열어 그 칸들이 지워졌는지 봤다.

전화번호 모양으로도 찾아봤는데, 걸린 것은 주문번호·송장번호였다. 숫자가 길면 비슷한 모양에 걸린다. **걸렸다고 끝이 아니라 열어서 무엇이 걸렸는지 본다.**

## 3. 배포가 마지막 커밋으로 됐는가

```bash
gh api repos/<계정>/<저장소>/pages/builds/latest --jq '.status + " " + .commit[0:7]'
```

`built 5a212d0` 처럼 나온다. **빌드된 커밋 번호가 방금 push한 번호와 같으면** 사이트가 최신이다.

## 4. 주소가 실제로 열리는가

```bash
curl -s -o /dev/null -w "%{http_code}\n" "https://<계정>.github.io/<저장소>/"
```

첫 주소, 대시보드 주소, 자바스크립트 파일, 설정 파일까지 모두 `200` 이었다. 화면 파일이 열려도 그 화면이 부르는 파일이 없으면 빈 화면이 된다. 그래서 부르는 파일까지 같이 본다.

파워셸에서는 `curl` 대신 `curl.exe`, `/dev/null` 대신 `NUL` 을 쓴다.

## 그대로 둔 것

점검하다 보면 고치고 싶은 게 더 나온다. 쓰지 않는 예전 샘플 파일, 팀원 코드 주석에 남은 예전 설명 같은 것들이다. 제출을 막는 문제가 아니라서 **그대로 두기로 했다.** 마감 직전에는 고칠 것보다 건드리지 않을 것을 정하는 게 더 중요하다.

## 남길 것

- 제출 전 점검은 **키 → 개인정보 → 빌드 커밋 → 주소** 순서로 내가 직접 본다
- 검색에 걸린 것은 열어서 진짜인지 확인한다
- 마감 직전 발견한 것은 "제출을 막는가"로 나눈다
