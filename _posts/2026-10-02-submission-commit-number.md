팀프로젝트 제출 문서에 "제출 버전 (커밋 번호)" 칸이 있었다. 처음에는 "마지막 커밋 시간"을 적는 줄 알았는데, 적어야 하는 것은 **커밋 번호**였다.

## 문제: 번호를 적으면 커밋이 또 생긴다

1. 문서를 다 고치고 커밋한다 → 커밋 번호 A가 생긴다
2. 문서에 A를 적는다 → 문서가 바뀌었으니 다시 커밋해야 한다 → 커밋 B가 생긴다
3. 문서에 적힌 번호는 A인데, 저장소의 마지막 커밋은 B다

자기 자신의 번호를 자기 안에 적을 수는 없다. 커밋 번호는 내용으로 계산되기 때문에, 번호를 적는 순간 내용이 바뀌고 번호도 바뀐다.

## 그래서 이렇게 했다

**적힌 번호 = 번호를 적기 바로 전 커밋**으로 정했다. 그 커밋에 제출할 코드와 문서가 다 들어 있으니 제출 버전으로 충분하다. B에서 바뀐 것은 번호 한 줄뿐이다.

[파워셸에 칠 것]

```powershell
cd C:\Users\ctale\Desktop\claudecode\sales-analysis
```

```powershell
git log -1 --format="%h %ad" --date=format:"%Y-%m-%d %H:%M"
```

- `-1`: 마지막 커밋 하나만
- `%h`: 짧은 커밋 번호, `%ad`: 커밋 시각
- `--date=format:`: 시각을 보기 좋은 모양으로

실제로는 이렇게 됐다.

| 커밋 | 내용 |
|---|---|
| `46d7343` | 문서 8개 올림 ← 문서에 적은 제출 버전 |
| `5a212d0` | 제출 버전 칸에 `46d7343` 적음 |

## push 뒤 확인

push한 다음 GitHub와 내 컴퓨터가 같은 커밋을 가리키는지 봤다.

```bash
git fetch origin
git log --oneline -1 origin/main
git log --oneline -1 main
```

두 줄이 같으면 올라간 것이다.

## 남길 것

- 제출 번호를 적는 커밋은 **번호 한 줄만** 바꾼다. 다른 수정을 섞으면 제출 버전과 실제 제출물이 달라진다
- push 뒤에는 `origin/main` 과 `main` 을 나란히 놓고 내가 비교한다
