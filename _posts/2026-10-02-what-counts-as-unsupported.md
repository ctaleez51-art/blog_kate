> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

팀프로젝트 제출 자료에는 "지원 / 미지원 분석" 표가 있다. 다시 읽어 보니 **지원은 5줄인데 미지원은 7줄**이었다. 그중 절반은 미지원이 아니었다.

## 미지원이 아니라 일부러 그렇게 만든 것

| 미지원 표에 있던 줄 | 실제 |
|---|---|
| AI가 새로 계산한 숫자 | AI가 숫자를 지어내지 않게 **일부러 막은 것**이다. 숫자는 코드가 계산하고 AI는 해석만 한다 |
| 바로 전 달이 없는 비교 (예: 6월과 9월만) | 엉뚱한 달끼리 비교하던 문제를 고치면서 **일부러 막은 것**이다 |
| 순매출 (매출 − 반품) | 매출은 반품 전 금액, 반품액은 따로 계산하도록 **식을 정해 둔 것**이다 |

막으려고 애쓴 것을 "미지원"이라고 쓰면, 읽는 사람은 못 해서 안 된 것으로 읽는다. 장점이 단점으로 바뀐다.

## 우리 서비스가 할 일이 아닌 것

| 미지원 표에 있던 줄 | 뜻 |
|---|---|
| 두 데이터셋 결합 | 매출 파일과 재고 파일 같은 다른 종류의 파일을 이어 붙여 분석 |
| DB 직접 연결 | CSV 대신 쇼핑몰 DB에 바로 접속 |
| 분석 코드 실행 | AI가 코드를 직접 짜서 돌려 분석 |

셋 다 엑셀·태블로·ChatGPT 같은 **범용 분석 도구**의 기능이다. 쇼핑몰 운영자가 CSV만 올리면 되는 우리 서비스와는 쓰는 사람이 다르다. 이런 식이면 미지원은 끝도 없이 적을 수 있다.

언제 들어간 문장인지 커밋 기록으로 찾아봤다.

```bash
git log --format="%h %ad %s" --date=short -S "DB 직접 연결"
```

`-S` 는 그 글자가 **새로 생기거나 사라진 커밋**만 보여 준다. 문서를 처음 만든 날 들어왔고, 실제 기능을 보고 쓴 근거는 어디에도 없었다.

## 남긴 기준

**쇼핑몰 매출 분석에서 보통 기대하는데 우리가 안 되는 것만** 미지원에 적는다.

남은 줄은 셋이다.

- 상품별 지표: 스마트스토어나 쿠팡 판매자 화면에도 기본으로 나오는 항목이라, 없다고 밝혀 두는 게 맞다
- 주별·일별 추이
- 쿠팡 외 채널의 경쟁가 진단

## 남길 것

- 미지원 줄마다 "**못 한 것**인가, **안 하기로 한 것**인가, **애초에 할 일이 아닌 것**인가"를 내가 나눠 본다
- 안 하기로 한 설계는 지원 쪽 설명에 넣는다
