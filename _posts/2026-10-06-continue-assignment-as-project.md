## 개인 프로젝트를 한 폴더로 모았다

작업 폴더 안에 개인 프로젝트 7개가 과제 폴더들과 섞여 있었다. `personal` 폴더를 만들어 그 안으로 옮겼다. 한글 파일 이름 때문에 고생한 뒤라 폴더 이름은 영어로 했다.

- 경로가 적힌 기록 파일 세 개의 경로를 같이 고쳤다
- 폴더를 옮겨도 GitHub 연결(`origin`)은 그대로다. 7개 모두 확인했다

```powershell
Get-ChildItem -Directory "<작업 폴더>\personal" | ForEach-Object { "{0}  {1}" -f $_.Name, (git -C $_.FullName remote get-url origin) }
```

## 과제를 최종 프로젝트로 이어 간다

과제로 제출한 "말로 쓰는 간편장부" PoC는 내가 개인적으로 만들 최종 프로젝트의 앞부분이다. 제출한 것은 그대로 두고, 개인 폴더에서 이어서 작업하기로 했다.

| | 과제 원본 | 개인 작업용 |
|---|---|---|
| 폴더 | 원래 자리 | `personal` 안에 새 이름 |
| 저장소 | 내 계정의 공개 저장소 (GitHub Pages) | 조직 아래 비공개 저장소 (새로 만듦) |
| 하는 일 | 제출한 그대로 둠 | 통째로 복사한 뒤 `origin` 만 바꿈 |

```powershell
git -C <복사한 폴더> remote set-url origin https://github.com/<조직>/<새 저장소>.git
git -C <복사한 폴더> remote -v
```

- 통째로 복사해서 **커밋 기록과 커밋 안 된 파일 8개**가 같이 들어왔다. 마지막 제출 커밋 때 "안 쓰는 파일"로 저장소에서 뺀 것들이다
- push 하면 **커밋된 것만** 올라간다. 8개 파일은 커밋해야 올라간다
- 원본 폴더의 `origin` 은 그대로 과제 저장소를 가리키는 것도 확인했다

## 남길 것

- 제출한 과제는 손대지 않고 **복사해서** 이어 간다. 제출물과 Pages 주소가 그대로 남는다
- 복사한 뒤에는 `git remote -v` 로 **원본과 복사본이 서로 다른 저장소를 가리키는지** 확인한다
- 폴더를 옮길 때는 그 경로가 적힌 기록 파일도 같이 찾아 고친다
