> 모두의연구소 AI 에이전트 과정 학습 기록입니다.
> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

지시를 구체적으로 안 하면 엉뚱하게 받아들여지고, 다투다가 끝내지 못한 일이 많았다. 그렇다고 매번 육하원칙을 다 적을 수는 없다. 그래서 **후보를 보여 주면 내가 고르는** 방식을 만들어 봤다.

## 내 육하원칙

1. 누가 2. 언제 3. 무엇을 4. 왜 5. 어떻게 6. 했나

- **했나** 는 앞의 다섯 가지에 대해 어떤 행동을 하는지다

## 실제 지시 하나로 나눠 봤다

GitHub 조직을 만들던 중 내가 한 질문이다.

> "아 됐고 그 원래 있는 계정하고 어떻게 연결되는 거야? 어디서 와야 되는 거야? 어디서 봐야 되냐고?"

| 항목 | Claude 가 나눈 것 | 내가 나눈 것 |
|---|---|---|
| 1. 누가 | 사용자님이 | **조직 계정이** |
| 2. 언제 | GitHub에서 조직을 만든 뒤 | (비움) |
| 3. 무엇을 | 만든 조직과 원래 계정의 관계를 | **원래 있는 계정하고 연결되어 있다는 화면을** |
| 4. 왜 | 조직이 계정과 따로 노는 건지 몰라서 | (비움) |
| 5. 어떻게 | GitHub 화면에서 어디로 들어가서 | 어떤 경로 또는 어떤 메뉴에서 |
| 6. 했나 | 확인한다 | 볼 수 있는 거냐 |

차이는 세 가지였다.

- **누가** 는 문법상 주어(보는 사람 = 나)가 아니라 **질문이 다루는 대상(조직 계정)** 이었다
- 질문에 없는 **언제·왜** 는 비워 뒀다. 억지로 채우면 지어낸 게 된다
- **무엇을** 은 "관계" 같은 뭉뚱그린 말이 아니라 **보고 싶은 화면** 이었다

그때 받은 답은 조직이 무엇인지 설명하고 링크를 주는 것이었다. 내가 물은 건 **첫 화면에서 메뉴로 가는 길**이었다.

이 예시를 잡으려면 화낸 문장이 아니라 **엇나가기 전에 내가 처음 한 지시**를 찾아야 했다.

## 선택 창 규칙

- 정해 둔 글자 하나만 입력하면 띄운다
- 항목마다 후보를 몇 개 보여 주고 내가 클릭한다. 맞는 후보가 없으면 그 항목은 안 고른다
- **직접 입력 칸은 넣지 않는다**
- 버튼은 **보내기** 와 **거부** 두 개

처음엔 스페이스 하나로 정했는데, 앱이 공백만 있는 메시지는 보내지 않아서 마침표(`.`) 하나로 바꿨다.

## 시험 결과

| 시험 | 결과 |
|---|---|
| 처음 만든 창(`<script>` + onclick) | 클릭해도 반응 없음 |
| 앱이 지원하는 폼 형식으로 다시 만든 창 | 클릭 됨 |
| 보내기 | 고른 것만 **입력칸에 채워진다.** Enter 를 한 번 더 눌러야 전달된다 |
| 안 고른 항목 | 빠지고 전달된다 |
| 거부 | 아직 안 눌러 봄 |

## 남길 것

- 시험 중에는 **시험 결과만** 본다. 채워진 내용에 대한 답을 받는 단계가 아니다
- 후보 방식은 간단한 일에는 오히려 번거롭다. 애매하거나 큰 일에 쓴다
