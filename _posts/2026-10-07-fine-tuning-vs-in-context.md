> 모두의연구소 AI 에이전트 과정 학습 기록입니다.
> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

## 왜 물었나

최종 프로젝트로 종합소득세 신고 앱을 만들고 있다. 자료를 올리면 장부를 쓰고, 세금을 계산하고, 홈택스에 낼 전자신고 파일까지 만드는 앱이다. 중간중간 AI 가 자료를 읽거나 질문에 답해야 한다.

그래서 AI 를 내 일에 맞추는 두 방법을 비교했다.

## 두 방식

- **파인튜닝**: 내 자료로 모델을 추가 학습시켜서, 모델 자체를 바꾼다
- **인컨텍스트 러닝**: 모델은 그대로 두고, 부를 때마다 지시문과 예시(영수증 예시와 정답 칸 같은 것)를 함께 넣는다

| | 파인튜닝 | 인컨텍스트 러닝 |
|---|---|---|
| 준비 | 학습 자료 수백~수천 건, 학습 비용·시간 | 지시문과 예시 몇 개 |
| 고치기 | 다시 학습 | 지시문만 고치면 바로 반영 |
| 세법이 해마다 바뀔 때 | 다시 학습 | 지시문·예시 교체 |
| 부를 때 비용 | 예시를 안 넣어도 돼서 입력이 짧음 | 예시만큼 입력이 길어짐 |
| 잘 맞는 일 | 정해진 형식을 아주 많이, 똑같이 반복 | 규칙이 바뀌거나 경우가 다양한 일 |

세무는 해마다 규칙이 바뀐다. 이 칸 하나만으로도 차이가 크다.

## 내 앱의 조건이 답을 바꾼다

앱 조건을 먼저 정했다.

- **exe 로 판다.** 웹 앱이 아니다
- **AI 요금은 사용자가 낸다.** 사용자가 자기 API 키를 넣는다

이 두 가지가 걸리는 곳이 있었다.

**API 키를 exe 안에 넣으면 안 된다.** 누구나 꺼내 쓸 수 있다. 내 키로 부르려면 중간에 내 서버를 둬야 하고, 그러면 쓸 때마다 요금이 내 계정에 나간다. 단품 판매와 맞지 않는다. 사용자 키로 부르면 내 서버도 필요 없고 내가 낼 것도 없다.

**파인튜닝한 모델은 학습시킨 계정에 묶인다.** 내가 내 계정으로 학습시킨 모델을, 사용자가 자기 키로 부르면 접근할 수 없다. 사용자 키 방식에서는 Claude 를 파인튜닝해 봐야 사용자가 못 쓴다. 게다가 Claude 는 파인튜닝할 수 있는 모델과 경로가 제한되어 있어 지금 되는지도 따로 확인해야 한다.

| 방식 | 사용자 키 + exe 조건에서 |
|---|---|
| Claude 파인튜닝 | 내 계정에 묶여 사용자가 못 씀 |
| 로컬 모델 파인튜닝 | 학습시켜 exe 에 넣어 팔 수 있음. 키 필요 없음 |
| 인컨텍스트 러닝 | Claude API 든 로컬 모델이든 그대로 쓸 수 있음 |

로컬 모델(Ollama 등)은 자료가 사용자 컴퓨터 밖으로 안 나가고 비용도 없다. 대신 앞 과제 PoC 에서 10건 중 7건 성공이었고, 사용자 컴퓨터 사양을 탄다.

## 정한 것과 안 정한 것

- 정한 것: exe, 사용자 API 키, 키는 사용자 컴퓨터에만 저장하고 밖으로 보내지 않는다
- 안 정한 것: Claude API 와 Agent SDK 중 무엇을 쓸지, 파인튜닝을 할지. **앱에서 AI 가 맡을 일이 정해진 뒤** 내가 판단한다

설명을 듣다가 "이 앱엔 이게 맞다"는 결론부터 들으면 판단할 근거가 안 남는다. 차이를 먼저 나란히 놓고, 고르는 건 내가 한다.

## 남길 것

- 파인튜닝은 모델을 바꾸고, 인컨텍스트 러닝은 매번 넣는 걸 바꾼다
- 누가 요금을 내느냐(누구 키로 부르느냐)가 파인튜닝 가능 여부까지 바꾼다
- 배포 방식과 요금 주체를 먼저 정하면 선택지가 저절로 줄어든다
