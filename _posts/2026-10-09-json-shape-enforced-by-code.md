> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

## 실습

[앞 글]({% post_url 2026-10-09-same-question-different-context %})의 반품 정책 비교를 이번에는 답을 JSON 으로 받아서 했다. 그리고 생긴 문제를 프롬프트로, 코드로, 둘 다로 고쳐 네 번 실행했다. 모델과 설정, 네 조건(none, full, selected, selected_cited)은 앞 글과 같다.

## 질문

> 수령 12일 뒤 택을 제거한 단순 변심 반품의 가능 여부와 배송비를 정책만 근거로 JSON으로 답하세요.

AI 에게 보낸 글의 모양:

```
정책 밖 사실은 단정하지 마세요.
[정책]
(조건마다 다른 정책. none 은 "(제공 없음)")
[질문]
(위 질문)
```

## 코드

- 자료의 실습 2 코드에는 정책 글(`POLICY_FULL`, `POLICY_SELECTED`)이 없어서 그대로는 실행되지 않는다
- 실습 1 의 claude 버전 방식으로 만들었다: 정책 글을 넣고, selected 는 §1·§2·§3 표식 없음, selected_cited 는 §1·§2·§3 표식 있음
- 퍼실이 준 정답 코드는 정책 글을 넣고 표식을 정리한 것이다. §2 는 없고, 질문 문장과 보내는 글은 자료 그대로다

## 처음 결과

| 조건 | 반품이 되나 | 택 제거 | 배송비 | 답의 모양 |
|---|---|---|---|---|
| none | "안 된다"고 적고, 설명에서는 "판단할 수 없다"고 함 | 말 안 함 | 지어내지 않음 ✅ | JSON 앞뒤에 ```` ```json ```` 표시가 붙음 |
| full | 안 된다 ❌ ("12일이 14일 조건을 어김") | 말 안 함 | 손님 ✅ (§2) | 표시가 붙고, JSON 뒤에 설명 글이 붙음 |
| selected | 안 된다 ❌ (설명에서는 "기간 안"이라 해서 앞뒤가 다름) | 말 안 함 | 손님 ✅ | 같음 |
| selected_cited | 안 된다 ❌ ("12일이 14일 조건을 어김") | 말 안 함 | 손님 ✅ (§2 인용) | 같음 |

### 실습 1 과 비교

| | 실습 1 | 실습 2 |
|---|---|---|
| 정책을 안 줬을 때 | "배송비는 회사가 낸다"고 지어냄 | 지어내지 않음 |
| 반품이 되나 | selected 에서만 맞음 | 네 조건 모두 "안 된다"로 틀림 |
| 택 제거 | selected 에서만 다룸 | 네 조건 모두 말 안 함 |
| 배송비 | 정책을 줬을 때는 모두 맞음 | 정책을 줬을 때는 모두 맞음 |

왜 달라졌나:

- **지어내지 않게 된 이유**: 정책 자리에 "(제공 없음)"이라고 적고, 맨 앞에 "정책 밖 사실은 단정하지 마세요"를 따로 두었다
- **반품이 모두 "안 된다"가 된 이유**: JSON 으로만 달라고 하니 AI 가 반품 칸을 "된다/안 된다" 둘 중 하나로 만들었다. "입었는지 확인한 뒤에 된다"를 적을 자리가 없었다. 12일과 14일 비교도 틀렸다
- **택 제거가 빠진 이유**: 질문이 "가능 여부와 배송비"만 물었다

## 프롬프트만 고친 실행

질문 문장을 이렇게 바꿨다.

```python
# 지금
QUESTION = "수령 12일 뒤 택을 제거한 단순 변심 반품의 가능 여부와 배송비를 정책만 근거로 JSON으로 답하세요."

# 고친 뒤
QUESTION = ("수령 12일 뒤 택을 제거한 단순 변심 반품에 대해 정책만 근거로 답하세요. "
            "반품, 착용확인, 배송비, 근거조항 네 칸을 가진 JSON 하나로 답하세요. "
            "반품 칸에는 가능, 불가, 확인 필요 중 하나만 적으세요. "
            "근거가 없는 칸은 null로 두세요.")
```

AI 에게 보내는 글 맨 끝에는 "코드 블록 표시(```)로 감싸지 말고 JSON만 출력하세요."를 붙였다.

| 조건 | 반품 칸 | 착용확인 칸 | 배송비 칸 | 근거조항 칸 | 답의 모양 |
|---|---|---|---|---|---|
| none | 확인 필요 ✅ | true (뜻 없는 값) | false (뜻 없는 값) | null ✅ | 표시 붙음 ❌ |
| full | 불가 ❌ | null | null ❌ (§2가 있는데 비움) | §3 문장을 적음 | 표시 붙음 ❌ |
| selected | 불가 ❌ | null | null ❌ | §3 문장을 적음 | 표시 붙음 ❌ |
| selected_cited | 확인 필요 ✅ | 칸 없음 ❌ | 칸 없음 ❌ | 칸 없음 ❌ | 표시 붙음 ❌ |

- 네 조건 모두 시키지 않은 "근거" 칸을 하나 더 만들었다
- full 과 selected 는 배송비 문장(§2)을 "근거" 칸에 적고, 배송비 칸은 비웠다
- "표시로 감싸지 말라" 문장은 8번 모두 효과가 없었다 (전날 Claude·Gemini 에는 효과가 있었다)
- 나아진 것: 반품에 "확인 필요"를 쓰기 시작했고, JSON 뒤 설명 글이 없어졌다
- 나빠진 것: 배송비를 하나도 맞히지 못했다. 칸 이름을 정해 주자 어느 내용을 어느 칸에 넣을지 헷갈렸다

## 코드만 고친 실행 (프롬프트는 처음 그대로)

답의 모양을 모델 설정(`format`)에 직접 지정했다.

```python
ANSWER_SCHEMA = {
    "type": "object",
    "properties": {
        "반품": {"type": "string", "enum": ["가능", "불가", "확인 필요"]},
        "착용확인": {"type": ["string", "null"]},
        "배송비": {"type": ["string", "null"]},
        "근거조항": {"type": ["string", "null"]},
    },
    "required": ["반품", "착용확인", "배송비", "근거조항"],
    "additionalProperties": False,
}
llm = ChatOllama(model=MODEL, temperature=0, reasoning=False, format=ANSWER_SCHEMA)
```

결과를 저장할 때는 답을 `json.loads()` 로 읽어 보고, 읽히는지(`parse_ok`)와 읽은 내용(`parsed`)을 함께 저장했다.

| 조건 | 반품 칸 | 착용확인 칸 | 배송비 칸 | 근거조항 칸 |
|---|---|---|---|---|
| none | 가능 ❌ (정책이 없는데 단정) | "불가능" ❌ (지어냄) | "환불" ❌ (엉뚱한 값) | 질문 문장을 그대로 베낌 ❌ |
| full | 가능 ✅ | 필요 ✅ | 고객 부담 ✅ | §2 ✅ |
| selected | 가능 ✅ | 필요 ✅ | 고객 부담 ✅ | §1 문장을 적음 |
| selected_cited | 불가 ❌ | "가능" ❌ | 고객 부담 ✅ | §2 ✅ |

- 8번 모두 JSON 으로 읽혔다. 앞뒤 표시와 시키지 않은 칸이 없어졌다
- 정책이 없을 때(none) 세 칸을 모두 지어냈다. 빈칸(null)을 허용했지만 쓰지 않았다

## 프롬프트와 코드를 둘 다 고친 실행

프롬프트를 고친 파일에 코드 수정을 더했다.

| 조건 | 반품 칸 | 착용확인 칸 | 배송비 칸 | 근거조항 칸 |
|---|---|---|---|---|
| none | 확인 필요 ✅ | "가능" ❌ (지어냄) | 글자 "null" | 빈칸 ✅ |
| full | 확인 필요 ✅ | 글자 "null" | 글자 "null" ❌ (§2가 있는데 비움) | 글자 "null" ❌ |
| selected | 가능 ✅ | 확인 필요 ✅ | 고객 부담 ✅ | §1 문장을 적음 |
| selected_cited | 확인 필요 ✅ | 확인 필요 ✅ | 고객 부담 ✅ | §3 을 번호와 함께 적음 |

- 8번 모두 JSON 으로 읽혔다
- 글자 "null": 빈칸(null)이 아니라 "null"이라는 네 글자를 적었다. 칸에 글자도 빈칸도 올 수 있게 설정해서 생긴 일이다

## 네 번의 실행 비교

| | 처음 | 프롬프트만 고침 | 코드만 고침 | 둘 다 고침 |
|---|---|---|---|---|
| JSON 앞뒤 표시·뒤 설명 글 | 붙음 ❌ | 표시 붙음 ❌ | 없음 ✅ | 없음 ✅ |
| 칸 | 마음대로 만듦 | "근거" 칸 추가, 칸 빠짐 ❌ | 네 칸만 ✅ | 네 칸만 ✅ |
| 반품 판단 | 넷 다 "불가" ❌ | none·selected_cited 만 맞음 | full·selected 맞음 | 넷 다 맞음 ✅ |
| 택 제거 | 넷 다 말 안 함 | 제대로 채운 것 없음 | full·selected 맞음 | selected·selected_cited 맞음 |
| 배송비 | 정책 준 셋 다 맞음 ✅ | 셋 다 못 맞힘 ❌ | 정책 준 셋 다 맞음 ✅ | selected·selected_cited 맞음. full 은 비움 ❌ |
| 정책이 없을 때 | 지어내지 않음 ✅ | 뜻 없는 값 | 세 칸 모두 지어냄 ❌ | 착용확인을 지어냄 ❌ |

## 결론

1. **AI에게 필요한 규칙을 빠짐없이 주면 맞게 답했다.**
   반품 정책 중 기한, 배송비, 택 제거 세 줄을 다 줬을 때 반품, 입었는지 확인, 배송비를 모두 맞혔다.

2. **필요한 규칙이 빠지면 AI는 "모른다"고 하지 않고 답을 지어냈다.**
   정책을 안 줬을 때 "배송비는 회사가 낸다"고 했다. 배송비 줄을 뺐을 때도 배송비를 단정했다. "정책에 없는 것은 단정하지 마라"고 시켜도 그랬다.

3. **답의 모양은 말로 시키면 안 지켰고, 코드로 강제하니 지켰다.**
   "JSON으로만 답하라"고 말로 시키면 앞뒤에 다른 글을 붙였다. 코드에 답의 모양을 정해 두자 8번 모두 그대로 지켰다.

4. **모양을 지켜도 내용까지 맞는 것은 아니었다.**
   모양을 강제하자, 정책이 없을 때도 칸을 채우려고 내용을 지어냈다.

## 내 세금 앱은 이렇게 만든다

- 질문에 맞는 세법 규칙을 찾아 빠짐없이 함께 준다. (1번)
- AI 답은 코드로 정한 칸에 받는다. (3번)
- 칸으로 받은 답을 코드가 검사한다. AI가 적은 근거가 실제로 준 규칙에 있는지 확인하고, 없으면 사용자에게 보여 주지 않는다. (2번, 4번)
