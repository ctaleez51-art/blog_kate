> 모두의연구소 AI 에이전트 과정 학습 기록입니다.
> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

## 따져 본 말

"규칙 파일·메모리·대화 기록은 다 user role 이라 시스템은 건드릴 수 없다"는 말이 맞는지 따져 보았다. 확인된 내용만 적는다.

## 1. Claude 모델과 Claude Code

| 이름 | 하는 일 |
|---|---|
| Claude 모델 (LLM) | 받은 글을 읽고 답을 쓴다. 명령을 "실행해 달라"고 요청만 하고, 직접 실행하지는 않는다. 파일도 직접 열지 못한다 |
| Claude Code (앱) | 파일을 열어 Claude 모델에게 글을 보내고, Claude 모델이 요청한 명령을 실제로 실행한다. 실행하기 전에 설정 파일을 본다 |

- Claude Code 는 한국어 문장의 뜻을 모른다. 정해진 모양의 글을 글자 그대로 맞춰 보는 일만 한다
- 그래서 규칙 파일의 문장은 Claude Code 가 뜻을 따지지 않고 Claude 모델에게 넘긴다. 읽고 따르는 것은 Claude 모델이다
- 규칙 파일에 적은 말을 안 지키는 것은 Claude Code 가 아니라 Claude 모델이다
- 승인 창을 띄우는 것은 Claude Code 이지만, 승인이 필요한 명령을 고르는 것은 Claude 모델이다

## 2. role 세 가지

Claude Code 는 Claude 모델에게 글을 보낼 때 글마다 "누가 쓴 글인지" 이름표(role)를 붙인다.

| role | 들어가는 글 | 누가 정하나 |
|---|---|---|
| system | "너는 Claude Code 다. 이렇게 일해라…" 같은 지시 | 회사. 나는 터미널에서 `claude` 를 실행할 때 `--append-system-prompt` 로 글을 덧붙일 수 있다 |
| user | 규칙 파일(CLAUDE.md), 메모리, 내 질문 | 나 |
| assistant | Claude 모델이 전에 쓴 답 | Claude 모델 |

- Agent SDK 로 직접 만든 프로그램에서는 `system_prompt` 로 system role 의 글을 내가 쓴다
- system role 은 user role 보다 무게가 크다. 그래도 Claude 모델이 읽고 따르는 글이라서, 어기지 못하게 막지는 못한다

## 3. 규칙 파일 (CLAUDE.md)

- 처음에는 없다. 회사가 만들지 않고 내가 만든다
- Claude Code 가 열어서 user role 로 Claude 모델에게 보낸다. 대화를 시작하자마자 Claude 모델이 읽은 상태가 된다
- 지켜지는지는 Claude 모델에 달렸다. 어겨도 막을 것이 없다

| 파일 | 언제 적용되나 |
|---|---|
| 글로벌 CLAUDE.md (`C:\Users\<사용자>\.claude\CLAUDE.md`) | 이 컴퓨터에서 어느 폴더에서 일하든 |
| 작업 폴더의 CLAUDE.md | 그 폴더와 그 안의 모든 폴더에서 |

- 둘 다 적용된다
- 안쪽 폴더에서 일해도 바깥 폴더의 CLAUDE.md 가 적용된다. 10월 7일 실습에서 안쪽 실습 폴더의 챗봇이 바깥 작업 폴더의 규칙을 따른 것이 이 경우다

## 4. 설정 파일

| 파일 | 언제 적용되나 |
|---|---|
| 글로벌 설정 파일 (`C:\Users\<사용자>\.claude\settings.json`) | 어느 폴더에서 일하든 |
| 작업 폴더의 설정 파일 (`.claude\settings.local.json`) | 그 폴더에서 일할 때 |

- **system role 이 아니다.** Claude 모델에게 보내지는 글이 아니다. Claude Code 가 따로 갖고 있다가, Claude 모델이 명령을 실행해 달라고 하면 이 목록을 보고 실행할지 막을지 정한다
- **회사가 만들지 않는다.** 처음에는 없다. 승인 창에서 "항상 허용"을 누르면 Claude Code 가 파일을 만들고 그 명령을 적는다. 누를 때마다 한 줄씩 늘어난다
- **내가 고칠 수 있다.** VS Code, 메모장으로 직접 고치거나, Claude 에게 허락하고 시킨다
- **허용 목록**: 적힌 명령은 승인 창 없이 실행된다 (푸는 쪽)
- **금지 목록**: 적힌 명령은 Claude 모델이 시켜도 Claude Code 가 실행하지 않는다 (막는 쪽). 내가 터미널에서 직접 치는 명령은 막히지 않는다

예: push 를 막으려면

```json
"deny": [
  "Bash(git push:*)",
  "PowerShell(git push:*)"
]
```

### 규칙 파일과 설정 파일의 차이

| | 규칙 파일 | 설정 파일 |
|---|---|---|
| 누가 보나 | Claude 모델 | Claude Code |
| 어떻게 지켜지나 | Claude 모델이 지켜야 지켜진다 | Claude 모델이 안 지켜도 Claude Code 가 막는다 |
| 무엇을 적나 | 한국어 문장 무엇이든 | 정해진 모양의 명령 |

### 설정 파일의 한계

1. 명령으로 된 것만 막는다. 반말, 말 바꾸기, 시키지 않은 제안 같은 것은 막을 수 없다. 이런 것은 계속 규칙 파일로 둔다
2. 적어 둔 글자 모양과 맞아야 막힌다. `git push` 로 시작하는 명령만 막아 두면 `git -C 폴더경로 push` 는 빠져나갈 수 있다
3. 허용은 글자가 똑같은 명령에만 적용된다. 폴더나 숫자가 조금만 달라도 승인 창이 다시 뜬다

## 5. 지금 내 설정 상태

- 작업 폴더의 설정 파일: 허용 목록 40줄, 금지 목록 0줄
  - 대부분 그때 한 번만 쓴 명령이다
  - 한글 파일 이름이 깨진 줄이 있다
  - 작업 폴더 밖(임시 폴더)을 다룬 노션 관련 줄이 10줄 있다
- 글로벌 설정 파일: 두 줄뿐
  - `"autoUpdatesChannel": "latest"` — 앱 업데이트를 나오는 즉시 받는다 (반대는 `"stable"`)
  - `"theme": "dark"` — 화면을 어두운 색으로
- 그래서 지금 push 와 삭제를 막는 것은 규칙 파일의 글뿐이다

## 6. 확인하지 못한 것

- 금지 목록에 `git * push` 처럼 가운데에 `*` 를 쓸 수 있는지
- 글로벌 CLAUDE.md 와 작업 폴더 CLAUDE.md 의 내용이 부딪힐 때 어느 쪽을 따르는지
- 데스크톱 앱 메뉴에 허용·금지 목록을 고치는 화면이 있는지 (없는 것으로 보이지만 확인 안 함)
- 데스크톱 앱에서 금지 목록이 실제로 막는지 (직접 시험 안 함)
- VS Code 에서 JSON 파일을 열었을 때 미리보기 메뉴가 안 보인 이유
