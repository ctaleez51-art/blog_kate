도구 설계 5번 노드 실습 2의 첫 단계다. 재고 도구를 코드로 직접 만들어 AI에게 주고, 한 바퀴를 돌려 봤다.

- 모델: qwen3.5:2b (Ollama), 온도 0, 생각 모드 끔
- 실행 명령

```powershell
uv run --python 3.13 --with langchain --with langchain-ollama python inventory_lab.py
```

## 한 바퀴

질문은 "BUSAN-02 창고의 SKU A-17 재고를 알려 줘"다.

```
[1] 모델의 요청: [('get_inventory', {'sku': 'A-17', 'warehouse_id': 'BUSAN-02'})]
[2] 하네스의 실행 결과: {"sku": "A-17", "warehouse_id": "BUSAN-02", "available_quantity": 7, "checked_at": "2026-08-27T01:55:00+09:00"}
[3] 결과를 읽은 최종 답: 승인된 창고 (BUSAN-02) 에서 상품 A-17 의 현재 가용 재고는 **7**개입니다.
```

| 줄 | 누가 | 한 일 |
|---|---|---|
| [1] | AI | "재고 도구를 써 달라. 상품은 A-17, 창고는 BUSAN-02"라고 **요청만** 했다. 직접 실행하지 않는다 |
| [2] | 프로그램 | 그 요청대로 실제 함수를 실행해서 7개, 확인 시각을 받았다 |
| [3] | AI | 프로그램이 돌려준 값을 보고 "7개입니다"라고 답했다 |

노드와 같은 결과다. 숫자 7에 굵은 글씨 표시가 하나 더 붙었을 뿐이다.

## 질문은 화면에 안 나온다

실행 화면에는 [1] [2] [3] 세 줄만 나온다. AI에게 보낸 질문은 코드 안에 적혀 있다.

```python
r1 = await llm_with_tools.ainvoke("BUSAN-02 창고의 SKU A-17 재고를 알려 줘")
```

이 괄호 안의 글이 사람이 AI에게 물었다고 치는 질문이다. 다음 실습에서 질문을 바꿀 때는 이 줄만 고친다.

## 배운 것

- AI가 [1]에서 그럴듯한 요청을 써도, [2]가 없으면 재고를 읽은 게 아니다.
- [2]가 성공해도, [3]에서 AI가 수량을 바꿔 말하면 결과를 제대로 쓴 게 아니다.
- 그래서 세 줄을 다 남겨야 어느 단계에서 틀렸는지 가릴 수 있다. 이 기록을 trace라고 부르고, 과제 저장소의 `traces` 폴더에 남겼다.
