> 모두의연구소 AI 에이전트 과정 학습 기록입니다.
> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

도구 설계 3번 노드의 실습 1이다. 재고를 알려 주는 도구 `get_inventory`의 설명서(도구 정의서)를 여섯 칸으로 쓰고,
AI가 실수한 사례 세 개를 보고 설명서의 어느 칸이 비어서 생긴 일인지 찾는다.

## 여섯 칸

| 칸 | 쓴 내용 |
|---|---|
| 이름 | `get_inventory` (재고를 가져온다) |
| 하는 일 한 문장 | 승인된 창고에 있는 특정 상품의 현재 수량을 보기만 한다. 바꾸지 않는다 |
| 쓰는 때·안 쓰는 때 | 쓰는 때: 어느 상품이 어느 창고에 몇 개 있는지 물을 때 / 안 쓰는 때: 수량을 바꾸라고 할 때, 창고나 상품 코드를 모를 때(먼저 묻는다), 주문·배송을 물을 때 |
| 인자 스키마 | 상품 코드 `sku`: 꼭 넣음, 3~32자 / 창고 `warehouse_id`: 꼭 넣음, `SEOUL-01`, `BUSAN-02` 둘 중 하나만 / 없으면 부르지 않고 묻는다 |
| 반환 형식 | 상품 코드, 창고, 수량, 확인 시각 네 가지만. 원가 같은 값은 돌려주지 않는다 |
| 실패 정의와 뒤 행동 | 없는 창고 → 다시 부르지 않고 창고를 묻는다 / 없는 상품 코드 → 비슷한 상품을 고르지 않고 코드를 묻는다 / 서버 오류 → 한 번만 다시, 또 안 되면 멈춘다 / 어떤 경우에도 수량을 짐작해 말하지 않는다 |

"인자 스키마"가 낯설었는데, **도구를 부를 때 AI가 채워 넣어야 하는 값과 그 값의 규칙**이다.
재고 도구라면 "어느 상품", "어느 창고" 두 값을 꼭 넣어야 하는지, 몇 글자여야 하는지, 어떤 값만 넣을 수 있는지를 정한 것이다.

## 실패 사례 세 개

| AI가 한 실수 | 비어 있던 칸 | 고친 문장 |
|---|---|---|
| 없는 창고 이름을 지어내서 같은 오류를 계속 냈다 | 인자 스키마, 실패 뒤 행동 | 허락 안 된 창고면 창고를 묻고, 다시 부르지 않는다 |
| 상품 코드를 모르면서 비슷한 상품을 골라 조회했다 | 인자 스키마, 실패 뒤 행동 | 상품 코드는 꼭 있어야 하고, 없으면 묻는다 |
| 원가를 답에 말해 버렸다 | 반환 형식 | 수량과 확인 시각만 가지고 답한다 |

정리를 마치고 나서 내가 물었다. **이 실습으로 어떻게 "AI 실수는 설명서 빈칸 때문"이라는 걸 알 수 있나?**

알 수 없다. 이 표의 답은 노드에 이미 나와 있던 것을 옮겼을 뿐이고, AI를 직접 돌려서 실수하는 것을 본 게 아니다.
그 말이 맞는지는 다음 실습에서 설명서를 한 곳씩 고쳐 다시 돌려 봐야 확인된다.

## 채점 기준도 미리 정해 둔다

실행하기 전에 "무엇을 보면 통과인지"를 먼저 정해 둔다. 다음 실습에서 실행 기록을 볼 때 쓴다.

| 기준 | 통과 조건 |
|---|---|
| 값을 규칙대로 넣었나 | 상품 코드와 허락된 창고만 넣었다 |
| 도구가 제대로 돌았나 | 수량이 나오거나, 정해진 오류가 나왔다 |
| 답이 결과를 따랐나 | 수량과 확인 시각만 가지고 답했다 |
| 오류 때 제대로 했나 | 수량을 짐작하지 않고 정해진 행동을 했다 |

## 못 한 것

노드에 "아래 코드는 두 설명을 제외한 계약을 고정합니다. 파일로 저장한 뒤 그대로 실행해 도구 정의를 확인합니다."라는 문장이 있는데,
그 뒤에 코드가 사이트에 빠져 있었다. 이 단계는 하지 못했다.
