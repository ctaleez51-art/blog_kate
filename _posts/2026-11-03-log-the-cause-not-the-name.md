## 수동 실행은 성공했는데, 요약이 실패했다

세법 뉴스레터를 GitHub Actions에서 수동 실행했다. 수집, Python 설치, Discord 발송, 결과 재커밋은 다 됐다. 그런데 새 글 1건의 요약이 실패했다.

```
③ 취재 실패 [국세청 보도자료] 주식 양도소득 기본공제 누락분, ... (APIConnectionError)
```

그 글은 버려지지 않고 제목·링크 목록으로 Discord에 실렸다. 예외 처리는 동작했다.

문제는 로그에 남은 것이 **오류 이름 하나뿐**이라는 것이었다. 이걸로는 왜 실패했는지 알 수 없다. 내가 그럴 거면 뭐하러 기록하냐고, 하려면 제대로 하라고 했다.

## APIConnectionError는 토큰 문제가 아니다

처음에는 토큰(키나 잔액)이 없는 건지 물었다. 아니었다. 키나 잔액 문제면 오류 이름이 다르다.

| 상황 | 오류 |
| --- | --- |
| 키가 아예 없음 | `OpenAIError` (요청을 보내기 전에 남) |
| 키가 틀림 | `AuthenticationError` (401) |
| 잔액·한도 없음 | `RateLimitError` (429, `insufficient_quota`) |
| 요청이 서버에 닿지 못함 | `APIConnectionError` ← 이번 오류 |

`APIConnectionError`는 요청이 OpenAI 서버까지 가지 못했거나, 보낸 뒤 응답을 받지 못했다는 뜻이다. 원인 후보는 두 가지였다.

- **일시적 네트워크 문제**: GitHub 서버와 OpenAI 사이의 연결이 잠깐 끊긴 경우
- **Secret 값에 줄바꿈이나 공백이 섞인 경우**: 키를 붙여 넣을 때 끝에 줄바꿈이 따라 들어가면, 요청을 보내기 전에 막혀서 같은 오류가 난다.

로그에 이름만 있어서 둘 중 무엇인지 가릴 수 없었다.

## 원인까지 기록하게 고쳤다

오류 이름만 적던 네 군데(수집 응답 없음, 요약 실패, 검수 실패, 발송 실패)를 고쳤다.

- 오류 이름뿐 아니라 **오류 메시지**와 **그 오류를 일으킨 원래 오류**까지 적는다. 파이썬 예외는 원래 오류를 `__cause__`(또는 `__context__`)에 품고 있어서, 그걸 따라가며 한 줄로 이었다.
- 같은 원인이 겹겹이 감싸여 두세 번 찍혀서, 같은 줄은 한 번만 적게 했다.

### 공개 로그라 비밀값은 가렸다

여기서 하나 더 걸렸다. 오류 메시지에는 비밀값이 그대로 들어갈 수 있다.

- 키 오류 메시지에는 **키 값**이 들어간다(`Illegal header value b'Bearer sk-...'`).
- Discord 발송 오류 메시지에는 **웹훅 주소**가 들어간다(`404 ... for url: https://discord.com/api/webhooks/...`).

저장소도 공개고 Actions 로그도 공개다. 그래서 메시지에 OpenAI 키나 Discord 웹훅 주소가 있으면 `***`로 바꿔서 적게 했다.

### 일부러 실패시켜 확인했다

진짜 키는 쓰지 않고 가짜 키와 가짜 웹훅으로 네 가지 실패를 만들었다.

| 경우 | 로그에 남은 원인 | 키·주소 노출 |
| --- | --- | --- |
| 키 끝에 줄바꿈 | `Illegal header value b'Bearer ***\n'` | 없음 |
| 연결 안 되는 주소(요약) | `ConnectionRefusedError: … 연결을 거부했으므로…` | 없음 |
| 연결 안 되는 주소(검수) | 위와 같음 | 없음 |
| 가짜 웹훅 | `404 … for url: ***?wait=true` | 없음 |

## 다시 돌리니 원인이 나왔다

```
③ 취재 실패 [...] (APIConnectionError: Connection error. ← LocalProtocolError: Illegal header value b'***')
```

`Illegal header value` — **GitHub Secret에 저장된 OpenAI 키 값에, 키에 들어갈 수 없는 글자가 섞여 있었다.** 그래서 요청이 OpenAI로 나가기 전에 막혔다. 로컬의 `.env` 키로는 잘 돌았으니, Secret에 붙여 넣는 과정에서 섞인 것이다. 어떤 글자였는지는 GitHub가 로그에서 값을 `***`로 가려서 알 수 없다.

내가 저장소 Settings → Secrets and variables → Actions에서 `OPENAI_API_KEY`를 키만 붙여 넣어 다시 등록했다. 다음 실행에서 수집, 요약, 검수, 발송, 재커밋이 모두 성공했다.

```
③ 취재   [국세청 보도자료] 국세청, 주식 양도소득 기본공제 누락분 4,687명에 21억 원 환급
④ 검수   1건 → 합격 1 · 목록으로 내림 0
⑤ 발행   핵심 1건 + 목록, 메시지 1개 — 발송 완료
```

## 실패 메시지는 지우지 않았다

Discord에는 같은 글이 목록으로만 실린 메시지가 두 개 남았다. 지울지 고민했는데 남겨 뒀다. "요약이 실패해도 글을 버리지 않고 목록으로 싣는다"는 예외 처리가 **실제로 동작한 기록**이라, 루브릭의 예외 처리 항목 근거가 된다. 보고서에도 실패 두 번을 표로 적었다.

## 남길 것

- 실패를 기록할 때는 **이름이 아니라 원인**을 남긴다. 이름만 남기면 기록한 의미가 없다.
- 공개되는 로그에 오류 메시지를 남길 때는 **비밀값이 섞이는지** 먼저 본다.
- 로컬에서는 되는데 서버에서만 안 되면, 서버에 넣은 값(Secret)부터 의심한다.

## 앱과 연결

- 앱의 오류 기록도 이름이 아니라 원인까지 남긴다. 사용자에게 보이거나 공개되는 곳에서는 키·주소를 가린다.
- 배포 환경에 키를 넣을 때 붙여 넣기로 줄바꿈·공백이 섞일 수 있다. 앱 코드에서 키 앞뒤 공백을 지우고 쓰는 방법도 있지만, 따옴표 같은 글자는 그걸로 못 막으니 넣을 때 확인하는 것이 먼저다.
