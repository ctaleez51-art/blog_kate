## 매일 12시에 돌게 해 두었다

세법 뉴스레터는 GitHub Actions 워크플로(`daily.yml`)로 매일 12:00(한국 시각)에 돌게 했다.

```yaml
on:
  schedule:
    - cron: "0 3 * * *"          # UTC 03:00 = 한국 12:00
  workflow_dispatch:             # 수동 실행
```

- Actions 서버 시각은 UTC라서, 한국 12시는 `0 3`이다.
- OpenAI 키와 Discord 웹훅 주소는 저장소 Secrets에 넣었다.
- Actions 환경은 실행이 끝나면 파일이 지워진다. 그래서 실행 뒤 갱신된 `seen.json`(이미 보낸 글 번호)과 `metrics.jsonl`(실행 기록)을 저장소에 다시 커밋한다. 이를 위해 `permissions: contents: write`를 줬다.

## 제출 전에 시험하려고 한 번짜리 예약을 더했다

12시 예약이 정말 도는지 제출 전에 보고 싶었다. 그래서 그날 13:30에 한 번만 도는 줄을 더했다.

```yaml
    - cron: "30 4 3 11 *"        # 11월 3일 UTC 04:30 = 한국 13:30
```

**내가 Actions 화면을 보고 있었는데, 돌지 않았다.**

GitHub 예약 실행은 정각을 보장하지 않는다. 늦게 돌기도 하고, 건너뛰기도 한다.

## 대안 세 가지

| 대안 | 내용 | 문제 |
| --- | --- | --- |
| 더 기다리기 | 늦게라도 돌 수 있음 | 건너뛸 수도 있어서, 마감날 기다리기만 하기는 위험 |
| 수동 실행 | Actions 화면이나 `gh workflow run`으로 실행(`workflow_dispatch`) | 실행 방법이 예약이 아니라 수동이라는 점만 다름 |
| 바깥 예약 서비스 | cron-job.org 같은 서비스가 정한 시각에 GitHub API를 불러 수동 실행을 시킴 | GitHub 토큰을 그 서비스에 넣어야 함 |

## 수동 실행으로 해도 과제에 문제가 없는지 먼저 확인했다

- 과제의 필수 5단계와 루브릭에는 "예약 실행"이 없다.
- 발행 단계의 조건은 "목표 채널에 실제로 전달되는지 확인"이다. 수동 실행으로도 확인된다.
- 수동 실행도 예약과 **같은 GitHub 서버에서 같은 작업**이 돈다. 해외 서버에서의 수집, Python 설치, Discord 발송, 결과 재커밋까지 다 확인된다.
- 예약 실행 시험은 과제 조건이 아니라, 제출 전에 자동 실행이 되는지 보려고 내가 정한 일이었다.

다만 보고서에는 "매일 12:00 자동 실행"이라고 적혀 있었다. 예약으로 실제 돈 기록이 없는 상태에서 그대로 두면 사실과 어긋난다.

## 결정

**자동 실행은 그대로 두고, 과제 제출용 실행만 수동 실행이라고 쓴다.**

1. 시험용 13:30 줄은 지웠다. 그대로 두면 내년 11월 3일에 또 돈다.
2. Actions에서 수동 실행했다.
3. 보고서 실행 기록에 "과제 제출용 실행은 수동 실행(`workflow_dispatch`), 평소에는 매일 12:00 예약 실행"이라고 적었다.

## 남길 것

- GitHub 예약 실행은 정각을 보장하지 않는다. 마감 직전에 처음 시험하면 안 된다.
- 막혔을 때는 대안을 고르기 전에, 그 대안이 **과제 조건에 맞는지**를 원문 조건과 대조해 본다.
- 계획을 바꾸면 보고서 문장도 사실에 맞게 바꾼다.
