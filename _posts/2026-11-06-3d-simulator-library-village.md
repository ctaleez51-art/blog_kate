## 퍼실이 준 것

딥리서치 실습이 끝나고 퍼실이 추천 과제를 줬다. 2일차 파이프라인을 한 파일로 정리한 `pipeline.py` 와, 그걸로 3D 시뮬레이터를 만드는 프롬프트다. 메모는 두 줄이었다.

- omo → opus 5.5 max로
- 이거 재현하지 마시고 여러분들의 것을 만들어 보시죠

프롬프트의 조건은 이랬다.

- `pipeline.py` 의 로직과 프롬프트는 고치지 말고, 모델 래퍼와 상속으로 이벤트를 뽑을 것
- 리서처는 병렬로 도니까 절 번호를 스레드별로 기록해 모든 이벤트에 붙일 것
- 키는 `.env` 에서 `OPENAI_API_KEY` 만 읽고, 화면·로그·브라우저로 내보내지 말 것
- 실행 모드(실제 호출 / 저장된 기록 재생)를 화면에 표시할 것
- 지난 실행을 디버거처럼 한 단계씩 넘겨 보는 재생 기능

## 만든 구조

| 파일 | 하는 일 |
|---|---|
| `pipeline.py` | 원본 그대로 |
| `simulator.py` | 모델 호출을 감싸 앞뒤로 이벤트를 남기고, `DeepResearch` 를 상속해 노드 시작·끝을 남김. 실행마다 `runs/*.json` 에 저장하고 내 PC 안(127.0.0.1)의 작은 웹서버로 브라우저에 실시간 전달 |
| `index.html` | 3D 화면 + 처음·이전·재생·다음·끝 버튼 |

이벤트 하나는 "몇 초에, 누가(몇 번 절의 리서처), 무엇을(읽기·고르기·쓰기), 몇 자"다. 시뮬레이터는 PowerShell 에서 켠다. 키가 내 PC에 있고, 끌 때까지 계속 켜져 있는 서버라서 노트북 셀로 돌리면 커널이 묶이기 때문이다.

`py -3.12 -m venv` 는 `No runtime installed that matches 3.12` 로 실패했다. 설치된 3.14로 만들었다. `pipeline.py` 는 3.11 이상이면 된다.

## 첫 실제 실행이 23.7초에 끊겼다

리서처 넷이 원고를 다 낸 순간, 기록 파일을 덮어쓰는 단계가 Windows 에서 거부됐다.

```
PermissionError: [WinError 5] 액세스가 거부되었습니다: '...\runs\run_20261105_172158.tmp' -> '...\runs\run_20261105_172158.json'
```

다른 프로그램이 파일을 잠깐 잡고 있으면 덮어쓰기가 거부될 수 있다. 몇 번 다시 시도하고, 그래도 안 되면 실행은 계속하도록 고쳤다. 기록 저장이 실패했다고 실험 전체가 죽으면 안 된다.

## "뭐가 이렇게 후다닥 지나가?"

시간 기록이 없어서가 아니었다. 이벤트마다 시각은 남아 있었다. 재생 화면이 이벤트 사이 간격을 최대 1.5초로 잘라서, 실제로 2~9초 걸린 모델 호출도 순식간에 지나갔다. 재생 방식에 "실제 걸린 시간대로"와 "한 단계씩 고르게"를 넣었다.

또 하나. 고친 파일을 PC에 저장했다고 했는데 다시 켜도 그대로였다. 확인해 보니 예전 파일이 들어가 있었다. 다시 저장하고 파일 내용이 같은지까지 확인받았다.

## 실행과 재생은 다르다

| 버튼 | 하는 일 | 비용 |
|---|---|---|
| 위쪽 **실행** | `pipeline.py` 를 새로 돌림. 실시간으로 따라감 | 실제 호출이면 듦 |
| 아래쪽 **▶ 재생** | 이미 기록된 실행을 다시 봄. 한 단계씩 넘김 | 없음 |

헷갈리는 이름이 하나 있다. 위쪽 모드의 "저장된 기록 재생"은 ▶ 재생이 아니라, 모델 대신 `결과자료.json` 의 답을 돌려주며 실행을 흉내 내는 **실행**이다.

## 나만의 것 — 도서관 마을

첫 화면은 퍼실 이미지처럼 우주에 구체가 떠 있는 모양이었다. 같은 이벤트 기록으로 장면은 얼마든지 바꿀 수 있어서, 도서관 마을로 바꿨다.

- **1층 서가**: 문서 34개 = 책장 34개. 문서끼리 링크된 책장 사이에는 바닥 길이 깔린다. 리서처가 걸어가서 책을 꺼내 읽고, 읽은 책장에는 자기 색 책갈피가 꽂힌다(관련 없던 책은 회색).
- **2층 단상**: 코디네이터와 편집자 책상. 1층과 2층 사이의 유리 난간이 컨텍스트 격리 경계다. 책(원문)은 1층에서만 읽고, 2층으로는 원고만 들고 올라간다.

캐릭터도 직접 만들었다. 기존 캐릭터는 저작권 때문에 쓸 수 없다. 첫 시안이 너무 단순해서 다시 만들었다.

| 캐릭터 | 모습 |
|---|---|
| 코디네이터 | 가르마 머리, 둥근 안경, 나비넥타이, 목차 두루마리 |
| 큰그림 담당 | 탐험모, 배낭 지도, 망원경 |
| 시간순 담당 | 똥머리, 가디건, 회중시계, 책 |
| 인물 담당 | 탐정모, 망토, 돋보기, 수첩 |
| 원인 담당 | 삐죽머리, 멜빵바지, 실타래와 핀 |
| 편집자 | 반다나, 귀에 꽂은 연필, 원고 더미, 큰 펜 |

## 시각화는 실습 전에 정해야 한다

처음 "시각화해줘"라고 했을 때 나온 것은 정적인 구조도였다. 내가 만들어 둔 시각화 스킬에는 "실습을 시작할 때 시각화할지 묻고, 하기로 하면 모델을 부르는 셀을 실행하기 **전에** 기록 코드를 넣는다"가 적혀 있다. 그런데 실습 시작 때 그 단계를 건너뛰어서, 실습은 시간 기록 없이 끝났다.

원인은 스킬이 읽히지 않은 것이었다. `claudecode\.claude\skills` 폴더의 스킬은 VS Code 의 Claude Code 가 읽는 자리이고, 이번에 쓴 Cowork 창은 계정에 등록된 스킬만 자동으로 불러온다. 두 실습 스킬을 계정 스킬로 등록했다.

- 스킬은 만드는 것으로 끝이 아니라, 쓰는 도구에서 실제로 읽히는지까지 확인한다.
- 시각화할 실습은 모델 셀을 돌리기 전에 기록 코드부터 넣는다.

## omo, ulw, opus max는 뭐였나

| 이름 | 뜻 |
|---|---|
| omo (oh-my-opencode) | OpenCode 에 붙이는 플러그인. 대장 AI 하나가 일을 나눠 여러 AI에게 동시에 맡긴다. 오늘 배운 코디네이터-리서처 구조와 같고, 보고서 대신 프로그램을 만든다 |
| ulw (ultrawork) | omo 에서 끝날 때까지 스스로 밀어붙이는 최대 작업 모드 키워드 |
| omc (oh-my-claudecode) | 같은 것을 Claude Code 용으로 만든 것 |
| opus 5.5 max | omo 가 부르는 모델을 Claude Opus 5.5로, 생각하는 양을 최대로 |

셋 다 공식 도구가 아니라 오픈소스다. 퍼실 프롬프트는 대화하며 고쳐 나가는 용도가 아니라 **한 번 던지면 끝까지 만들도록 쓴 작업 지시서**였다. 가상환경부터 3D 화면, 재생 디버거까지 큰일을 사람이 중간에 손대지 않고 PC에서 실제 호출로 시험하며 완성하려면, 그 정도 도구와 모델이 필요했던 것으로 보인다.

"재현하지 말라"는 결과물을 똑같이 만들지 말라는 뜻이지, omo를 쓰지 말라는 뜻이 아니다. 이번엔 Cowork 창에서 omo 없이 만들었다. omo로 하려면 터미널에서 OpenCode 를 켜고 `/models` 에서 모델을 고른 뒤 프롬프트를 붙여 넣으면 된다. 내 OpenCode 에는 Claude 가 목록에 없어서 `opencode.cmd auth login` 으로 Anthropic API 키부터 연결해야 했다. Opus 는 가장 비싼 등급이고 ulw 는 토큰을 많이 쓰니, 콘솔에서 사용 한도를 먼저 정해 둔다.
