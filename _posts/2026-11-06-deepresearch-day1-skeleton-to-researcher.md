> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

## 무엇을 만드나

질문 하나를 넣으면 스스로 자료를 읽고 장문의 보고서를 쓰는 딥리서치 에이전트다. 주제는 한국 근대사, 질문은 처음부터 끝까지 하나다.

> 1894년에 일어난 주요 사건들은 무엇이고 각각의 원인은 무엇인가?

자료는 위키백과 문서 34건(447,487자, 문서끼리 링크 428개)이다. 약 22만 토큰이라 `gpt-4o-mini` 가 한 번에 읽을 수 있는 12만 8천 토큰을 넘는다. 그래서 에이전트 하나가 다 읽지 않고, **코디네이터가 목차를 나누고 리서처 여럿이 절을 하나씩 맡아 필요한 문서만 읽는** 구조로 만든다.

1일차에는 노드 여섯 개(① 기획 ② 배치 ③ 조사 ④ 점검 ⑤ 종합 ⑥ 평가)를 빈 채로 먼저 이어 붙여 한 바퀴 돌리고(동작하는 뼈대), 그중 ①②③을 진짜로 갈아 끼웠다.

## 설치 셀부터 오류 — Windows 에서는 `!` 줄 끝의 `#` 가 주석이 아니다

교안 설치 셀을 VS Code 에서 돌리자 이게 나왔다.

```
ERROR: Invalid requirement: '#': Expected package name at the start of dependency specifier
```

문제의 줄은 이것이다.

```python
!pip install -q -U "brotli>=1.2.0"   # 이미지의 brotli 1.1.0 이 httpx2 와 충돌 → 모든 LLM 호출이 실패한다
```

교안은 Colab(리눅스) 기준이라 `#` 뒤를 주석으로 처리한다. Windows 에서는 `!` 로 실행하는 줄 안의 `#` 를 주석으로 보지 않아서, pip 가 `#` 과 그 뒤 한글까지 설치할 패키지 이름으로 받았다. 주석을 윗줄로 옮기니 오류가 없어졌다.

같이 나온 `[notice] A new release of pip…` 는 오류가 아니라 pip 새 버전 알림이다. 설치 줄 하나에 한 번씩 나온다.

## 배정은 누가 하나 — 코디네이터는 모델이 아니라 역할

① 기획 노드를 끼우고 돌린 결과다.

```
① 기획   목차 4절 · 인물 담당→«동학 농민 혁명» · 시간순 담당→«청일 전쟁» · 원인 담당→«갑오개혁» · 큰그림 담당→«을미사변»
```

목차와 배정은 `gpt-4o-mini` 가 했다. 코드는 목록에 없는 문서나 다른 절과 겹치는 문서만 바로잡는다. 코디네이터는 모델 이름이 아니라 역할이다. 같은 `gpt-4o-mini` 가 "너는 리서치 팀의 코디네이터다"라는 프롬프트를 받으면 코디네이터가 되고, 문서를 받아 원고를 쓰면 리서처가 된다.

결과를 질문과 나란히 놓고 보니 이상한 점이 둘 있었다.

- 《을미사변》은 문서 첫 줄에 1895년 10월 8일 사건으로 나온다. 1894년 질문에서 벗어난 배정이다.
- 네 절이 받은 지시는 모두 "원인을 분석한다"인데 역할은 넷 다 다르게 붙었다. 사건 절에 인물 담당이 붙었다. 절 성격에 맞춰 고른 것이 아니라 명단을 하나씩 나눠 준 것에 가깝다.

코드는 형식(문서가 목록에 있나, 겹치지 않나)만 검사한다. 내용이 질문에 맞는지는 판단하지 못한다.

## 노드를 갈아 끼울 때마다 목차가 바뀌었다

③ 조사 노드까지 끼우고 돌렸더니 목차가 달랐다.

| 절 | ① 기획 셀 | ③ 조사 셀 |
|---|---|---|
| 1 | 인물 담당 → 동학 농민 혁명 | **큰그림 담당** → 동학 농민 혁명 |
| 2 | 시간순 담당 → 청일 전쟁 | 시간순 담당 → 청일 전쟁 |
| 3 | 원인 담당 → 갑오개혁 | 원인 담당 → 갑오개혁 |
| 4 | 큰그림 담당 → 을미사변 | **인물 담당 → 임오군란** |

실습 셀들은 노드 함수를 새로 정의한 뒤 마지막에 `run()` 을 부른다. `run()` 은 앞 셀의 결과를 이어받지 않고 질문을 넣어 ① 기획부터 다시 돌린다. 그래서 셀마다 모델이 목차를 새로 짰다. 교안도 "노드 하나를 수정해도 전체 과정을 다시 실행한다"고 적어 두었다. `temperature=0` 이어도 결과가 매번 같지는 않았다.

## ③ 조사 결과를 열어 보니

로그는 이랬다.

```
   ③ 큰그림 담당 «동학 농민 혁명» 3건 읽고 705자 · 인용 12곳 · 충분
   ③ 시간순 담당 «청일 전쟁» 3건 읽고 611자 · 인용 8곳 · 충분
   ③ 원인 담당 «갑오개혁» 3건 읽고 571자 · 인용 9곳 · 충분
   ③ 인물 담당 «임오군란» 3건 읽고 553자 · 인용 0곳 · 충분
```

저장된 결과 파일까지 열어서 교안의 확인 항목 넷을 대조했다.

| 확인 항목 | 결과 |
|---|---|
| 절마다 3건씩 읽었나 | 네 절 모두 3건 |
| 인용 0곳인 절이 있나 | «임오군란» 553자에 인용 0곳. 그런데 자기평가는 "충분" |
| 허위 인용이 있나 | 없음 (인용한 문서는 모두 실제로 읽은 문서) |
| 같은 문서를 여러 절이 읽었나 | 《갑신정변》을 세 절이 각각 읽음. 셋 다 인용하지 않음 |

《갑신정변》이 막히지 않은 이유는 1바퀴 `피하기` 목록에 **다른 절의 시작 문서만** 들어가기 때문이다. 누구의 시작 문서도 아니었으니 모두가 읽을 수 있었다.

하나 더 있었다. «임오군란» 절이 《갑신정변》을 읽은 요약이 "임오군란의 주요 인물은 김옥균, 박영효…"로 시작했다. 갑신정변의 인물을 지시(임오군란 인물)에 억지로 맞춘 것이다. 프롬프트에는 "관련 없으면 '관련 없음'이라고만 답하라"는 탈출구가 있는데, 그리로 가지 않았다. 《임오군란》 자체도 1882년 사건이라 질문 범위 밖이다.

## 정리

- 질문 범위를 벗어난 배정, 인용 없는 절, 엉뚱하게 붙은 요약은 모두 **오류 없이** 지나갔다. 코드는 형식만 본다.
- 셀마다 그래프가 처음부터 다시 돌아서, 셀끼리 결과를 나란히 놓고 비교할 수 없다. 이 문제는 2일차의 평가 지표로 이어진다.
- 나는 결과가 나오면 질문과 절 제목, 문서 첫 줄의 연도를 나란히 놓고 확인한다.
