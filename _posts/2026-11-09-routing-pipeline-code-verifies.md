> 모두의연구소 AI 에이전트 과정 학습 기록입니다.
> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

## 모델을 바꾼 이유

PRD 에는 로컬 Ollama `qwen3.5:2b` 로 적혀 있었다. RAG 과제에서 쓴 모델이다. 그런데 RAG 과제에서 이 모델이 금액 크기 비교와 출생연도를 자주 틀렸다. 그래서 cs-agent 실습과 같은 OpenAI 모델로 바꿨다.

- 판정: `gpt-5.6-luna`
- 답변·채점: `gpt-5.6-terra`

API 키는 과제 폴더의 `.env` 에서 읽는다. `.env` 는 `.gitignore` 에 넣어 저장소에 올리지 않는다.

## 흐름 (LangGraph)

```
classify → (OTHER 또는 확신도 0.5 미만) → handoff
   ↓
retrieve → answer → (NO_ANSWER) → handoff
              ↓
           verify → 통과 → 끝
              → 위반 1번째 → answer 다시
              → 위반 2번째 → handoff
```

넘기는(handoff) 길이 세 군데 있다. 판정에서, 답변에서, 검증에서다.

## classify — 판정과 넘기기 결정을 나눴다

판정 노드는 카테고리 1~2개와 확신도만 낸다. **넘길지 말지는 판정 노드가 정하지 않는다.** 다음 갈림길이 확신도를 임계값 0.5와 비교해서 정한다.

판정은 모델이 하고, 넘기기는 코드의 규칙이 한다.

## retrieve — 도구는 코드가 부른다

판정된 카테고리마다 근거 조회 도구(`lookup_family` 등)를 하나씩 부른다. 모델이 어떤 도구를 쓸지 고르지 않는다. 카테고리가 정해지면 코드가 해당 도구를 부른다.

## answer — 근거로 답할 수 없으면 한 단어

근거에만 기대어 답하고, `[QA-019]` 처럼 근거 번호를 붙이게 했다. 근거로 답할 수 없으면 `NO_ANSWER` 한 단어만 쓰게 했다. 이 한 단어가 나오면 넘기는 길로 간다.

## verify — 모델이 아니라 코드가 검사한다

실습 7장 가드레일과 같은 방식이다. 검사 규칙은 세 가지다.

1. 답변 속 10 이상인 숫자가 조립한 근거나 질문에 없으면 위반
2. 답에 붙인 근거 번호가 조립한 근거 밖이면 위반
3. 근거 번호가 하나도 없어도 위반

위반이 처음이면 답변을 다시 쓰게 하고, 두 번째면 넘긴다.

이 검사로는 **숫자가 없는 오답**을 못 잡는다. "가능"을 "불가"로 바꿔 말해도 숫자와 근거 번호만 맞으면 통과한다.

## 정리

- 나는 판정(모델)과 넘기기 결정(코드 규칙)을 나눈다.
- 도구 선택처럼 규칙으로 정할 수 있는 것은 모델에게 맡기지 않는다.
- 검증은 코드로 한다. 그리고 그 검사가 무엇을 못 잡는지도 같이 적어 둔다.

## 앱과 연결

- 신고 앱에서도 답변 속 숫자는 코드로 근거와 대조한다. 숫자가 없는 오답("가능"↔"불가")은 이 검사로 못 잡는다는 한계를 기억한다.
- 금액 비교(연금 5,166,667원 기준)나 출생연도 계산은 모델이 아니라 코드로 하는 편이 안전하다. 이번 과제에서는 계산 도구를 넣지 않았다.
