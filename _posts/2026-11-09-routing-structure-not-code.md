> 모두의연구소 AI 에이전트 과정 학습 기록입니다.
> Claude와의 대화 내용을 Claude가 초안으로 정리하고, 제가 검토·수정했습니다.
{: .prompt-info }

## 과제가 요구한 것

교안 「고객 응대 에이전트 만들기 — 라우팅과 그라운딩」 10장은 라우팅 에이전트를 직접 만드는 실습 프로젝트다. 실습 코드(cs-agent)를 그대로 가져다 쓰는 과제가 아니다. 교안 표현으로는 "배운 것은 고객응대가 아니라 구조"다. 실습에서 익힌 구조를 다른 주제로 옮기는 것이 과제다.

구조는 네 단계다.

1. 입력을 받아 카테고리를 판정한다
2. 카테고리별로 근거를 조립한다
3. 근거만으로 답한다
4. 답을 검증하고, 모르겠으면 넘긴다

실습 각 장이 과제의 어느 파일로 이어지는지 표로 맞춰 봤다.

| cs-agent 실습 | 과제 파일 |
|---|---|
| 2장 라우트 정하기, fewshot/eval 분리 | 카테고리·매핑표, `data/goldenset.json` 예시용·평가용 |
| 3~4장 LLM 라우터, 확신도 임계값 0.5 | `agent.py` 판정과 넘기기 |
| 5장 매뉴얼 장 단위 쪼개기, 라우트별 컨텍스트 조립 | `context.py` |
| 6장 답변 프롬프트 | `prompts.py`, `agent.py` 답변 |
| 7장 가드레일(출처 없는 숫자 차단) | `agent.py` 검증 |
| 8장 채점기, 채점기 자체 검증 | `evaluate.py` |

## 폴더 이름은 예시였다

교안의 폴더 구조에는 `my-routing-agent/` 라고 적혀 있다. 그런데 바로 위에 "아래 구조는 예시입니다"라는 문장이 있고, 저장소 이름을 정해 주는 문장은 없다. 그래서 폴더와 저장소 이름을 `tax-routing-agent` 로 바꿨다.

이름을 바꿀 때는 이름이 적힌 곳을 다 찾아서 같이 바꿨다. HANDOFF 파일 이름, 파일 안 링크, 실습 HANDOFF 의 링크까지다. 교안 정리본 안의 `my-routing-agent/` 는 교안 원문이라 그대로 뒀다.

## 주제와 자료 — 검색형 챗봇에서 틀린 질문들

주제는 인적공제 상담이다. RAG 가이드 챗봇 과제에서 쓴 자료를 그대로 썼다.

- 국세상담센터 인적공제 Q&A — 묶음 13개, 질문 107개. 질문 하나를 조각 하나로, 번호 QA-001 ~ QA-107
- 키워드 연말정산 인적공제 18항목 — 항목 하나를 조각 하나로, 번호는 항목 번호 그대로 KW-06 ~ KW-99

같은 자료로 검색형 챗봇을 만들었을 때 틀린 질문들이 있었다. 대부분 관계없는 조각을 같이 가져와 섞은 것이었다.

- ⑤ 어머니 국민연금 600만원 → "가능"이라고 답함. 5,166,667원을 넘으니 안 된다
- ⑪ 25세 장애인 동생 → "20세 이하 또는 60세 이상" 나이요건이 필요하다고 답함

라우팅으로 바꾸면 카테고리에 맞는 자료만 프롬프트에 들어간다. 이 오답들이 사라지는지가 이번 과제에서 확인할 것이었다.

## 카테고리는 자료가 이미 나눠 둔 묶음에서

카테고리는 자료가 이미 나눠 둔 묶음을 기준으로 정했다. 질문 종류마다 판단 규칙이 다르기 때문이다.

| 카테고리 | 다루는 질문 | 넣는 자료 | 조각 / 글자 |
|---|---|---|---|
| `FAMILY` | 누가 기본공제 대상 가족인가 | Q&A 09~14, 키워드 19·23·24·28·31·34·39·63·84·98 | 47 / 약 20,700 |
| `INCOME` | 가족 소득이 100만원 이하인가 | Q&A ※연간소득금액, 키워드 19 | 28 / 약 11,000 |
| `EXTRA` | 경로우대·장애인·부녀자·한부모 | Q&A 15~18, 키워드 06·42·63·71·89 | 31 / 약 11,600 |
| `CREDIT` | 자녀·출산·혼인 세액공제 | Q&A 06·33, 키워드 66·67·90·99 | 21 / 약 7,400 |
| `OTHER` | 위 넷이 아닌 것 → 넘김 | 없음 | 0 |

자료 전체는 약 10만 글자다. 어느 카테고리든 매핑된 부분만 프롬프트에 들어간다.

## PRD 에 [결정 필요]로 남겨 둔 것들

PRD 를 쓸 때 정하지 못하고 남겨 둔 것을 이번에 정했다.

- 키워드 63 인적공제는 기본공제 표와 추가공제 표가 한 항목에 같이 있다. 나누지 않고 `FAMILY`·`EXTRA` 둘 다에 넣었다.
- `INCOME` 은 키워드 자료에 전용 항목이 없다. 키워드 19 기본공제를 같이 넣었다.
- 두 카테고리에 걸친 질문(⑩ 연금 금액 + 경로우대)이 있다. 판정이 카테고리를 최대 2개 고르고, 두 카테고리 근거를 겹치지 않게 합쳐 넣는다. 분류 점수는 맨 앞 카테고리로 잰다.
- 넘기기 임계값은 실습과 같은 0.5, 데모는 streamlit, 공개 배포는 하지 않는다.

## 정리

- 과제에서 내가 옮긴 것은 코드가 아니라 구조다. 실습 장마다 과제 파일이 하나씩 대응한다.
- 교안의 예시 이름은 정해진 이름이 아니다. 앞뒤 문장을 같이 읽고, 바꿀 때는 이름이 적힌 곳을 다 찾아서 같이 바꾼다.
- 카테고리는 자료가 이미 나눠 둔 구분에서 시작하면 매핑표가 바로 나온다.

## 앱과 연결

- 신고 앱의 상담 기능도 질문을 먼저 종류별로 나누고, 그 종류에 맞는 자료 부분만 근거로 줘야 한다. 자료 전체를 주면 다른 규칙(예: 장애인 형제자매에게 일반 나이요건)이 섞인다.
- 카테고리는 국세상담 Q&A 묶음이나 법령 조문 체계처럼 자료가 이미 나눠 둔 구분에서 시작한다.
